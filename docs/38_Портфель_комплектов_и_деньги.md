# Круг 14. Портфель комплектов и деньги, которые держит непредъявление

Круг 13 отвечал на вопрос «можно ли сдать **здесь**». Руководителю нужен следующий:
**«где мы стоим по всем объектам и сколько это стоит»**. Круг 14 связывает вердикты по объектам
с суммами актов КС-2 и раскладывает деньги по действию: что закрывается подписью сегодня, а что
требует собирать данные.

## 1. Пробел, который воспроизводился

| Что происходило | Чем это плохо |
|---|---|
| Восемь отчётов по объектам читались по одному, потом кто-то сводил их в таблицу руками | сводка живёт до первой правки: вердикт в письме и вердикт в папке расходятся |
| «Комплект не сдан» и «деньги стоят» обсуждались отдельно | непонятно, что чинить первым: подписать три реестра или переделать журнал верификации |
| Объект, по которому комплект вообще не начинали, выглядел в сводке как «0 ₽ риска» | ноль читается как «там всё чисто», хотя там просто ничего нет |
| У акта не заполнена сумма — в сводке появляется 0 | то же самое, только внутри объекта |
| Один сводный акт попадал в две строки портфеля | риск удваивался, и его несли в отчёт руководству |
| Суммы по разделам складывали и получали больше, чем есть денег | акт, заявленный в двух разделах, считался дважды |

## 2. Что сделано

Новый модуль `pto_agent/pack_portfolio.py` (схема `pto-agent/pack-portfolio@1`),
CLI `pack portfolio --config`, MCP-инструмент `pack_portfolio` (34-й), 16 страж-тестов и
сквозной скрипт `scripts/check_pack_portfolio.py` (27 правил в CI).

Комплект каждого объекта собирается **тем же `build_pack`**, что и в круге 13: сводка не может
расходиться с папкой объекта, потому что это одна и та же функция.

### Конфиг портфеля

```json
{
 "portfolio": "Портфель ПТО, ноябрь 2026",
 "objects": [
  {"object_name": "ЖК «Северный», корпус 2", "pack_number": "К-38",
   "pack": "data/demo/pack/pack.json",
   "acts": [
    {"act_id": "КС-2 №38", "period": "октябрь 2026", "amount_rub": 34106600.0,
     "source": "data/demo/acts/acts.json",
     "covered_by": ["submittals", "quality_docs", "journals_verification"]},
    {"act_id": "КС-2 №37", "period": "сентябрь 2026", "amount_rub": 248000.0,
     "covered_by": ["rd"]}]},
  {"object_name": "Склад комплектации, Шушары", "pack": "…/warehouse_pack.json",
   "acts": [{"act_id": "КС-2 №5", "amount_rub": 2300000.0, "covered_by": ["journals_work"]}]},
  {"object_name": "Детский сад, Колпино", "acts": [{"act_id": "КС-2 №2", "amount_rub": 1870000.0},
                                                   {"act_id": "КС-2 №3"}]}
 ]
}
```

`pack` — путь к конфигу комплекта или сам конфиг; `acts` — список или ссылка на реестр актов
(`amount_rub`, `month`). `covered_by` необязателен: он нужен только для разреза «раздел → деньги».

### Шесть правил денег

1. **Сумма берётся из акта с источником.** `amount_rub` (или `amount`) из реестра актов;
   в отчёте у каждой строки указан файл-источник. Строка «2 300 000,50» читается, `nan`, `≤ 0`
   и «нет поля» — нет.
2. **Нет суммы — «не оценено», а не 0 ₽.** Код `ACT_WITHOUT_AMOUNT` и строка в списке
   «не оценено» с причиной.
3. **Объект без комплекта — тоже «не оценено».** `OBJECT_WITHOUT_PACK`: вердикта нет, значит и
   риска не посчитать. В таблице у такого объекта стоит «не оценено», а не «0,00 ₽».
4. **Повторённый акт считается один раз.** `ACT_DOUBLE_COUNTED`, и вторая строка уходит
   в «не оценено» с пометкой, что акт уже учтён по другому объекту.
5. **Разрез «раздел → деньги» — только по заявленным актам.** Раздел, который акт не назвал
   в `covered_by`, денег не получает; в таблице так и написано: «акты этот раздел не заявляли —
   деньги к нему не отнесены». Разрез **не складывается** с итогом, и это сказано в отчёте:
   акт, заявленный в двух разделах, показан в каждом.
6. **Деньги разложены по действию.** «Поставить подписи», «устранить ошибки в разделах»,
   «собрать отсутствующие разделы», «обосновать исключение», «устранить ошибки и поставить
   подписи», «и данные, и ошибки, и подписи». Деньги попадают в «снимается подписью» **только
   если во всём комплекте нет ни одной ошибки и ни одного отсутствующего раздела** — иначе это
   было бы обещание, которое не выполняется.

Разрез по разделам показывает, что именно держит самые большие деньги на К-38:

Три раздела держат один и тот же акт №38 — и это видно: суммы в разрезе не складываются,
итог по портфелю считается по актам, а не по разделам.

## 4. Что показывает «снимается подписью»

Сценарий из CI (`scripts/check_pack_portfolio.py`): комплект собран полностью, ошибок нет,
но один раздел не подписан человеком.

```
объект «без подписи»: fix = «поставить подписи», деньги 2 000 000 ₽
объект «чистый»:      can_submit = да, деньги 5 000 000 ₽ освобождены
```

Два объекта, две разные работы: один закрывается подписью за вечер, второй уже предъявлен.
Если бы в комплекте была хоть одна ошибка, деньги ушли бы не в «подписи», а в
«устранить ошибки и поставить подписи» — проверка на это есть и в тестах, и в CI.

## 5. Как пользоваться

```bash
# сводка по портфелю: объекты, вердикты, деньги по актам
python3 -m pto_agent pack --out out/pack_portfolio portfolio \
        --config data/demo/pack_portfolio/portfolio.json

# код возврата: 0 — есть хотя бы один предъявляемый объект и нет блокеров сводки, 2 — иначе
```

Файлы в `out/pack_portfolio/`: `portfolio_<имя>.json`, `.md`, `.xlsx` (листы «Объекты», «Акты»,
«Разделы и деньги», «Блокеры»), `.docx` — сводка на одну страницу с местами подписей
«подготовил / проверил / решение о предъявлении принял». Комплекты объектов лежат рядом,
в подпапках `К-38`, `К-12` — со всеми разделами.

MCP: `pack_portfolio` (`config` или `config_path`), 33 → **34 инструмента**,
`prompts/tools_schema.json` версии 2.5.0.

## 6. Страж-тесты и CI

`tests/test_pack_portfolio.py` — **16 тестов**: объект без комплекта — «не оценено», а не 0;
акт без суммы — «не оценено»; строка «2 300 000,50» читается, `nan`/`−5`/отсутствие поля — нет;
заблокированный объект держит деньги, предъявляемый — нет; «снимается подписью» отделено от
«и данные, и ошибки»; повтор акта считается один раз; разрез по разделам строится только по
`covered_by` и не складывается с итогом; неизвестный раздел в `covered_by` — предупреждение;
пустой портфель — ошибка; демо-портфель; файлы и формулировки; CLI (код 2); MCP через stdio.

`scripts/check_pack_portfolio.py` — **27 правил**:

```

36 654 600.00 ₽ · не оценено 2 · чистый объект: предъявляется
нарушений: 0
```

## 7. Чего портфель не делает

- **Не придумывает суммы.** Нет акта или суммы — «не оценено» с причиной, а не среднее по
  объекту.
- **Не складывает разрез с итогом.** Разрез по разделам — для приоритета работ, итог — по актам.
- **Не обещает, что подпись всё решит.** «Снимается подписью» ставится только там, где кроме
  подписи действительно ничего не нужно.
- **Не принимает решения.** В отчёте три подписи: подготовил, проверил, решение о предъявлении
  принял — их ставит человек.
