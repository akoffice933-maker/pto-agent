# Круг 24: закрытие месяца (этап 3 завершён)

Ядро учёта (круг 23) записывало факты. Закрытие превращает факты в результат: косвенные
расходы уходят в затраты, затраты — в себестоимость сданных работ, НДС зачитывается,
субсчета 90/91 сворачиваются так, что на 99 появляется прибыль или убыток.

```bash
# что выбрано в учётной политике и чего в ней нет
python3 -m pto_agent ledger policy
python3 -m pto_agent ledger policy --markdown

# сухой прогон: считает цепочкой, журнал не трогает
python3 -m pto_agent ledger close --state out/ledger/state.json --period 2026-10 \
    --invoices data/demo/accounting/invoices_2026_10.json --dry-run

# закрытие
python3 -m pto_agent ledger close --state out/ledger/state.json --period 2026-10 \
    --invoices data/demo/accounting/invoices_2026_10.json --stock out/stock/state.json

# режим «только предлагать» (вариант C плана): проводки ждут решения человека
python3 -m pto_agent ledger close --state out/ledger/state.json --period 2026-10 \
    --invoices data/demo/accounting/invoices_2026_10.json --mode предлагать
python3 -m pto_agent ledger proposals --state out/ledger/state.json
python3 -m pto_agent ledger accept --state out/ledger/state.json --proposal Пр-0001
python3 -m pto_agent ledger reject --state out/ledger/state.json --proposal Пр-0002 \
    --reason "не в этом месяце"
```

## Семь шагов, и каждый отчитывается

| Шаг | Что делает | Что сказал на демо |
|---|---|---|
| 25/26 → 20.01 | 25 (собран по объектам) переносится как есть; 26 (общий) — по базе прямых затрат | 150 000 по захватке + 50 000 по базе 100 % |
| 20.01 → 90.02 | только по объектам с признанной выручкой; остальное — НЗП | без подписанных актов: **НЗП 2 626 500 ₽**, ничего не списано |
| 19.03 → 68.02 | по зарегистрированным СФ и только если сумма сходится | зачтено 304 800 ₽, **осталось 299 200 ₽** — нет СФ к УПД №119 |
| 90.01/90.02/90.03 → 90.09 | свёртка субсчетов с сохранением аналитики | 40 927 920 + 2 826 500 + 6 821 320 |
| 91.01/91.02 → 91.09 | то же для прочих доходов и расходов | не требуется: оборотов нет |
| 90.09/91.09 → 99 | прибыль или убыток | **прибыль 31 280 100 ₽** (сценарий с подписанным актом) |
| 94 (недостачи) | **не закрывается** — это решение человека | 10 640 ₽ остаётся, варианты перечислены |

## Три решения, которые пришлось принять и записать

**1. Затраты без подписанного акта не списываются.** Работа не сдана — затраты остаются
незавершённым производством. Это не «забыли закрыть»: на демо без подписи 20.01 остаётся
2 626 500 ₽ и это названо прямо. Альтернатива (списать всё в себестоимость месяца) дала бы
красивый убыток, которого нет.

**2. Аналитика затрат и выручки живут в разных разрезах — их надо сводить.** Прораб пишет
по захваткам («корпус 2, плита»), договор — по объекту («ЖК «Северный», корпус 2»). Пока
свёртки нет, 20.01 и 90.02 не встречаются **никогда**. Свёртка — запись в учётной политике
(`analytics.object.rollup`), а не догадка программы: нет свёртки — закрытие отказывается
и называет захватки, которые не сведены.

**3. 94 не закрывается автоматически.** Решение «в затраты / на виновного / в прочие
расходы» принимает человек. Автоматика здесь означала бы, что программа решила, кто виноват.

## Найденная и исправленная ошибка круга 23

При НДС «сверху» долг заказчика считался неправильно: `Дт 62.01` = 34 106 600 вместо
40 927 920, то есть без НДС. Журнал при этом сходился (обе стороны были одинаково занижены),
и заметить это можно было только глазами. Исправлено: в правило добавлен вид суммы
`receivable` = без НДС + НДС; 90.01 показывается с НДС (вариант А), налог снимается строкой
90.03. Тест `test_signed_act_receivable_includes_vat_when_vat_is_on_top` держит это.

Это ровно тот случай, ради которого сделана сверка: сальдо сходится — не значит «верно».

## Режим «предлагать» (вариант C плана)

Один движок, режим — настройка. В режиме `предлагать` проводки не пишутся в журнал, а ложатся
в предложения: их видно (`ledger proposals`), их можно принять (`accept` — станет проводкой)
или отклонить (`reject` — останется след с причиной). Период при этом **не закрывается**:
закрывать месяц предложениями нельзя.

На демо: 3 предложения (затраты, НДС, закрытие продаж), принято одно, отклонено одно,
одно осталось ждать.
