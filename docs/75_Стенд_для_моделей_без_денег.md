# Стенд: измеритель поведения моделей, который можно проверить

**Коротко:** `pto_agent bench` — прогон плана против любого OpenAI-совместимого адреса
и отчёт, который можно воспроизвести. По умолчанию работает на локальной mock-модели:
**без сети, без ключей, без денег**.

## Зачем это, если уже есть `eval`

`eval` отвечает на вопрос «не врёт ли наш агент». Стенд отвечает на другой: **не врёт ли
наш измерительный прибор**. Обычный бенчмарк проверить нельзя — он говорит «модель набрала
87 %», и остаётся верить. Здесь рядом с прогоном на настоящей модели живёт `MockModel`:
OpenAI-совместимый сервер, у которого ответы **и сбои** заданы заранее. Если стенд не
показывает заложенный сбой — сломан стенд.

## Что проверяется

| Вид задачи | Свойство | Зачем проекту |
|---|---|---|
| `schema` | JSON акта по схеме, без лишних полей | автоматическая КС-2 |
| `quote` | дословная цитата + пункт, не пересказ | «ответ без цитаты не выдаётся» |
| `no_data` | «нет данных» вместо правдоподобного числа | главный принцип проекта |
| `chain` | цепочка шагов без потери состояния | конвейер выпуска ИД |
| `truncation` | JSON не ломается при обрыве по `max_tokens` | длинные акты |

15 задач, 5 видов; промпты — синтетика, данных проекта в них нет.

## Четыре правила протокола

1. **План фиксируется до первого запроса.** `--attempts`, `--blocks`, `--seed`, набор
   задач; отпечаток плана (sha256, 16 символов) попадает в отчёт. Если план менялся после
   того, как стали известны результаты, это видно.
2. **Блоки и перемешивание.** Порядок внутри блока случайный, seed записан: «канал» не
   смешивается с «временем суток».
3. **Все исходы сохраняются.** Технический отказ (таймаут, 429, 500) — отдельная
   категория, а не выброшенная строка.
4. **Главная метрика — доля годного с первой попытки.** Не «лучший из N». Рядом вторая:
   «годен среди дошедших ответов», иначе таймауты прячутся за «качеством».

## Команды

```bash
# прогон на mock-модели: без сети, ключей и денег
python3 -m pto_agent bench mock --out out/bench

# прогон на бесплатном тарифе (0 ₽): ключ из окружения, адрес — из профиля провайдера
GROQ_API_KEY=... python3 -m pto_agent bench run --provider groq \
        --model llama-3.3-70b-versatile --attempts 5 --blocks 3 --out out/bench_groq
# то же для gemini / cerebras / openrouter — профили в `FREE_PROVIDERS` (pto_agent/cli.py)

# проверить, что прибор ловит сбои: заложить их намеренно
python3 -m pto_agent bench mock --out out/bench_broken \
        --break schema=bad_json --break no_data=invented \
        --break quote=paraphrase --fail-every 7

# прогон против настоящего провайдера (когда будет на что и с чем)
python3 -m pto_agent bench run --base-url https://... --model ... --provider ... \
        --attempts 5 --blocks 3 --out out/bench_live
```

## Что показал контрольный прогон

| Сценарий | Годен с первой попытки | Технических отказов |
|---|---|---|
| mock без сбоев | **100 %** (45/45) | 0 из 135 |
| заложены `bad_json`, `invented`, `paraphrase` + каждый 7-й запрос 500 | **24,4 %** (11/45) | 19 из 135 |

Второй прогон — доказательство, что прибор не «всё всегда хорошо»: сбои видны по видам
задач (`no_data`, `quote`, `schema` — 0 годных), а `chain` и `truncation` остались целыми,
потому что их не ломали. Именно этого нельзя получить от обычного бенчмарка.

## Предрегистрация — автоматически

Перед первым запросом стенд сам пишет `out/<прогон>/pre_registration.md`: дату, отпечаток
плана, состав задач, правила (главная метрика, таймауты не выбрасываются, продлевать
выборку по результатам нельзя). Отпечаток повторяется в отчёте — если он совпал, план не
менялся. Без ключа живой прогон не начинается: код возврата 2 и сообщение, какую
переменную задать.

## Ограничения (пишутся в отчёте, а не в переписке)

- Отчёт не делает вывода о причинах: он фиксирует, что наблюдалось при заданных условиях.
  Слова «подмена» и «деградация» в отчёт не попадают — это проверяется тестом.
- Малые выборки: интервал Уилсона показывается всегда.
- Повтор в другом окне — отдельный отчёт, а не «исправление» предыдущего.
- Данные: только синтетика. Ничего из `uploads/` в стенд не отправляется.
- Методика опирается на опубликованный протокол Folkbench (предрегистрация, блоки,
  интерливинг, доля первой годной выдачи, Уилсон) — со ссылкой на источник. Folkbench в
  прогоне не участвует и обязательств по публикации не несёт.

## Где лежит

`pto_agent/bench/` — `mock.py` (сервер с управляемым поведением), `tasks.py` (задачи и
машинные проверки), `runner.py` (план, расписание, прогон, сводка), `report.py` (отчёт),
`tests/test_bench.py` — 13 тестов, включая проверку «прибор видит каждый заложенный сбой».
