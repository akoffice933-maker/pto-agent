# Круг 49. Проверка трёх «пробелов» фактами: что подтвердилось, что нет

Запрос: «найди в интернете либо GitHub **пробел**» по трём пунктам — (1) ТЕР в открытых данных
ФГИС ЦС только федеральная база, сборники ТЕР — региональные сайты и PDF; (2) индексы пересчёта —
письма Минстроя, ручной импорт; (3) реестр отчётности и данные заказчика — данные организации,
внешнего источника не существует.

Проверка велась не рассуждением, а запросами к API и разбором скачанных файлов. Каждый вывод ниже
подкреплён командой, которую можно повторить.

**Итог одной строкой:** два пункта из трёх оказались неверны в части «только PDF / только руками»,
третий подтверждён частично — источник существует, но из этой среды недостижим.

| пункт | как было заявлено | что показала проверка | вердикт |
|---|---|---|---|
| индексы пересчёта | письма Минстроя, ручной импорт | письма лежат в **открытом API ФГИС ЦС** деревом документов; скачиваются без авторизации, разбираются в CSV | **пробела нет** — была не найдена автоматизация, а не источник |
| ТЕР | только федеральная база, сборники — PDF на региональных сайтах | реквизиты **всех** региональных сборников есть в ФРСН через API (846 записей); таблиц расценок нет ни в API, ни в ФСНБ | **подтверждено частично**: реестр открыт, расценки — нет |
| реестр отчётности / данные заказчика | внешнего источника не существует | источник **есть** (ЕИС: FTP + реестр контрактов), но из песочницы недостижим: FTP не отдаёт баннер, HTTPS обрывает TLS | **не подтверждено**, но и не опровергнуто экспериментом — нужен доступ из другой сети |

## 1. Индексы пересчёта: не PDF-руками, а открытый API

Раньше считалось, что индексы — это «письма Минстроя, которые человек скачивает и заносит
руками». Источник действительно письма, но они **опубликованы в API ФГИС ЦС** как документы:

```
GET /api/NormLegalDocPublished?limit=100&normLegalDocPublishedType=10&state=20
    &normLegalDocBaseKind=40&parentGuid=<год>       → кварталы
    ...&parentGuid=<квартал>                        → 2 узла (по группам ресурсов / по объектам)
    ...&parentGuid=<узел>                           → листья-письма: number, name, filePath (uuid)
GET /api/values/GetFileContent/<uuid>               → PDF
```

Авторизация не запрашивается. III квартал 2026 — 6 писем:

| письмо | файл (uuid) | размер |
|---|---|---|
| 45358-ИФ/09 от 23.07.2026 | `d465eb3f-8c79-4289-a7bd-3765632b7c69` | 12,0 МБ, 100 стр. |
| 46728-ИФ/09 от 30.07.2026 | `4a127ad8-256f-49d4-9d3c-03cb5048d168` | 6,7 МБ, 56 стр. |
| 50058-ИФ/09 от 13.08.2026 | `862c733b-d85e-4992-885a-554a72e10675` | 5,7 МБ, 39 стр. |
| 52419-ИФ/09 от 24.08.2026 | `bc9f5446-a9f3-4bc7-9b59-d31cbbacd558` | 0,5 МБ, 1 стр. |
| 53691-АЛ/09 от 28.08.2026 | `73448900-e21e-456a-ad5b-b9dc8f4e5f7e` | 23,5 МБ, 69 стр. |
| 58705-ИФ/09 от 21.09.2026 | `1ae7a169-f0f8-4199-81d5-0938e0e90d0c` | 0,5 МБ, 2 стр. |

### Что сделано в коде

`scripts/import_indices.py` — скачивание дерева и разбор PDF в «длинную» таблицу
`data/indices/minstroy_indices.csv.gz`: одна строка = одно значение.

```
quarter, letter, table_label, table_title, subject_no, subject, column, column_title, value, page
```

Почему «длинная», а не «по колонке на вид индекса»: состав приложений в письмах **разный**.
В 53691-АЛ/09 есть приложение «Автомобильные дороги / Искусственные дорожные сооружения»,
в 45358-ИФ/09 его нет вовсе, зато есть «перевозка грузов автомобильным транспортом».
Широкая таблица молча потеряла бы это различие.

**Разобрано 2 905 значений из 6 писем** (в скобках — сколько из них прочерков «-»):

| письмо | значений |
|---|---|
| 45358-ИФ/09 | 435 |
| 46728-ИФ/09 | 1 142 |
| 53691-АЛ/09 | 1 312 |
| 58705-ИФ/09 | 16 |
| 50058-ИФ/09, 52419-ИФ/09 | 0 — в этих письмах нет таблиц вида «№ п/п \| субъект \| числа» (текстовые разъяснения и одна страница приложения) |

`table_title` — дословная шапка таблицы со страницы PDF, `page` — страница. Поэтому любую цифру
можно открыть в PDF и сверить. Подписи колонок (`column_title`) взяты из шапки приложения, а не
придуманы: для «Автомобильных дорог» — «Автомобильные дороги» / «Искусственные дорожные
сооружения», для перевозок — типы подвижного состава.

Пример (Краснодарский край, III кв. 2026, письмо 53691-АЛ/09, стр. 52 PDF):

| вид индекса | значение |
|---|---|
| Автомобильные дороги | 12,66 |
| Искусственные дорожные сооружения | 20,02 |

В коде: `pto_agent/indices.py`, команда `takeoff indices --subject "Краснодарский край"`.
Тесты: `tests/test_indices.py` (9 штук), в том числе «прочерк — это `None`, а не ноль» и
«неизвестный субъект не подставляется».

### Чего автоматизация не покрывает — прямо

Разбираются таблицы вида «№ п/п | субъект | числа». Приложения «по объектам строительства»
и «по элементам прямых затрат» свёрстаны с объединёнными ячейками и повёрнутыми заголовками
(например, стр. 6 PDF: колонка «Московская область» набрана вертикально по буквам). Они
остаются только в PDF; количество разобранных значений указано как **факт** (2 905), а не как
«сколько должно быть». Это записано и в `meta.json`, и в выводе команды.

Отдельно: `IndicesOfChangeEstimatedPrice` — эндпоинт, который по названию должен отдавать
индексы — при всех комбинациях параметров возвращает `{"total":0,"items":[]}`. То есть в API
есть документы-письма, но нет нормализованной таблицы индексов. Проверено повторно 18.11.2026.

## 2. ТЕР: реестр открыт, расценок в машиночитаемом виде нет

Заявление «в открытых данных ФГИС ЦС только федеральная база» **верно для расценок**
и **неверно для реквизитов**.

### Что есть

```
GET /api/FrsnEdition/section                      → разделы; раздел 3 = территориальные нормативы
GET /api/FrsnEdition/Estimate/Section?section=6   → 845 записей (ТЕР, бюджет)
GET /api/FrsnEdition/Estimate/Section?section=7   → 1 запись (ТЕР без средств федерального бюджета)
```

Актуальность реестра на дату запроса: **06.11.2026**. Записей всего **846**; регион удаётся
выделить из наименования у **605** записей (30 субъектов), у **241** записи регион в названии
не указан — они внесены общей формулировкой. Это ограничение самого реестра, а не разбора:
где региона в названии нет, колонка `region` пустая, а не заполненная догадкой.

Пример (Краснодарский край — 3 записи):

| наименование | приказ | рег. номер |
|---|---|---|
| Территориальные сметные нормативы… на материалы, изделия и конструкции | Приказ Минстроя России от 31.12.2014 № 937/пр | от 22.01.2015 № 220 |
| Изменения в ТЕР Краснодарского края (ремонтно-строительные и строительные работы) | Письмо Минрегиона России от 09.04.2012 № 8238-ИП/08 | от 04.04.2012 № 124 |
| Территориальные единичные расценки Краснодарского края | Письмо Минрегиона России от 26.10.2010 № 36854-ИП/08 | от 26.10.2010 № 47 |

В коде: `scripts/import_ter_registry.py` → `data/ter/ter_registry.csv.gz` (+ meta),
`pto_agent/ter.py`, команда `takeoff ter --region "Краснодарский край"`.
Тесты: `tests/test_ter_registry.py`.

### Чего нет — и это проверено, а не предположено

1. **Таблиц расценок ТЕР нет в API ФРСН.** `FrsnEdition/Estimate/Section` отдаёт наименование,
   приказ, регистрационный номер, `editionId` и ссылку — и всё. Поля с расценками отсутствуют.
2. **ТЕР нет в архиве ФСНБ-2022.** Разбор официального ZIP через `zipfile`: 7 XML —
   ГЭСН, ГЭСНм, ГЭСНмр, ГЭСНп, ГЭСНр, ФСБЦ_Мат&Оборуд, ФСБЦ_Маш. Ни одного файла ТЕР.
   (grep по «ТЕР» в этих XML даёт ложные срабатывания — это слово «диаметр».)
3. **Ссылки реестра ведут на недоступный хост.** 662 записи имеют ссылку, но 648 из них —
   один и тот же адрес `http://www.minstroyrf.ru/trades/view.territorial.php`. Проверка
   18.11.2026: DNS отдаёт `82.202.190.8`, TCP/TLS не отвечает (`curl` код 000),
   `fetch_page` → HTTP 500. Скачать сборники по ссылкам реестра из этой среды нельзя.
4. **GitHub не содержит данных ТЕР.** Поиск репозиториев и кода по «ФРСН», «ТЕР расценки»,
   «ггэ смета», «smeta parser» — репозиториев с таблицами ТЕР нет. Ближайшее по смыслу —
   `https://github.com/proovcme/fgis-mcp` (MIT), где в `docs/SOURCE_INVENTORY.md` то же
   разделение: ТЕР = подразделы 6/7 ФРСН с внешними ссылками, региональные сайты не
   скрапятся. `https://github.com/ErvSed/smeta-fsnb-data` — SQLite из открытых данных
   `7707082071-fsnb`, 56 192 нормы, только федеральная база.

**Вывод по пункту 2:** «сборники ТЕР — региональные сайты, PDF» — верно; «в открытых данных
только федеральная база» — верно для расценок, но реестр реквизитов открыт и машиночитаем.
Добавленная ценность: теперь по любому региону можно автоматически получить список сборников
с приказами, а не искать их вручную.

Оговорка, которую нельзя опускать: наличие записи в реестре **не означает**, что сборник
действует в актуальной редакции. Реестр даёт реквизиты внесения, а не актуальность.

## 3. Реестр отчётности и данные заказчика: источник есть, но из песочницы недостижим

Это единственный пункт, где проверка не дала окончательного ответа, и я это фиксирую как есть.

Что известно: реестр контрактов и отчётности по 44-ФЗ публикуется в ЕИС (`zakupki.gov.ru`),
включая FTP-выгрузку открытых данных. На GitHub есть рабочие инструменты, которые с этой
выгрузкой работают: `Homyakin/ZakupkiParser` (MIT, Java, планы/договоры/извещения с FTP),
`aksyuk/zakupki_gov_ru` (MIT, R-скрипты загрузки FTP по 44-ФЗ),
`stufently/free-zakupki-gov-ru-monitor` (MIT, RSS реестра контрактов). Значит, источник
данных существует и машиночитаем.

Что показала проверка **из этой среды**:

| проверка | результат |
|---|---|
| DNS `zakupki.gov.ru` | 95.167.245.92 (резолвится) |
| TCP 21 / 80 / 443 | порты открыты |
| HTTPS `curl https://zakupki.gov.ru/` | TLS Client Hello уходит, ответа нет (код 000) |
| `fetch_page https://zakupki.gov.ru/epz/contract/search/results.html` | HTTP 500 |
| FTP `ftp://zakupki.gov.ru/` | соединение устанавливается, но баннер 220 не приходит: `curl: (56) response reading failed` |
| DNS `ftp.zakupki.gov.ru` | не резолвится |

Вывод: **утверждение «внешнего источника не существует» неверно** — источник есть. Но
утверждение «данные заказчика — только данные организации» **остаётся верным для нас**:
пока канал недостижим, эти данные можно получить только от заказчика. Разница
принципиальная: это ограничение доступа из конкретной сети, а не отсутствие источника.
Требуется либо запуск импортёра из сети с доступом к ЕИС, либо официальная выгрузка.

Дополнительно: `data.gov.ru` в 2026 году отдаёт JS-SPA на любой путь (включая
`/api/json/dataset` и `/opendata/{id}`) — прежний API открытых данных не работает.
`www.minstroyrf.gov.ru` из песочницы недоступен.

## Честный список «не сделано»

1. **Расценки ТЕР не получены.** Ни одной таблицы ТЕР в машиночитаемом виде в открытых
   источниках нет; сборники — PDF/платные базы, ссылки реестра ведут на недоступный хост.
   В базе знаний ТЕР по-прежнему отсутствуют, демо-ставки остаются как fallback с пометкой.
2. **Разобрано не всё содержимое писем.** Приложения «по объектам строительства» и «по
   элементам прямых затрат» (объединённые ячейки, вертикальные заголовки) в CSV не попали.
   В письмах 50058-ИФ/09 и 52419-ИФ/09 таблиц нужного вида нет вообще — 0 значений.
3. **ЕИС не проверен содержательно.** Из песочницы канал не работает; вывод «источник есть»
   сделан по косвенным признакам (работающие сторонние парсеры), а не по скачанным данным.
4. **Индексы не подключены к расчёту сметы.** Модуль отдаёт значение с источником, но
   пересчёт базисной стоимости в текущую автоматически не выполняется — это отдельная работа:
   нужно решить, к каким именно позициям применяется каждая колонка.
5. **Актуальность редакций ТЕР не проверена.** Реестр даёт реквизиты внесения, а не статус
   «действует в редакции такой-то».
