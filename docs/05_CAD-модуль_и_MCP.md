# CAD-модуль и MCP-обёртка: что собрано и как проверить

**Версия:** 0.1.0 · **Дата:** 03.11.2026 · **Статус:** работающий модуль, прогон на демо-чертеже пройден

Модуль добавляет к агенту ПТО работу с чертежами: чтение DXF без GUI (headless, ezdxf),
проверку по корпоративному шаблону, пометки по найденным расхождениям, применение изменений
только после подтверждения человеком и сверку объёмов «схема ↔ акт». Всё это отдано наружу
как MCP-инструменты — агент (или IDE, или Claude Desktop) вызывает их по протоколу.

## 2. Запуск

```bash
python3 scripts/make_demo_dxf.py                                  # демо-чертёж + PNG-предпросмотр
python3 -m pto_agent cad inventory --file drawings/korpus2_plan_v1.dxf
python3 -m pto_agent cad validate  --file drawings/korpus2_plan_v1.dxf        # код возврата 1, если выпуск запрещён
python3 -m pto_agent cad plan      --file drawings/korpus2_plan_v1.dxf --summary out/summary.json
python3 -m pto_agent cad apply     --file drawings/korpus2_plan_v1.dxf --plan out/cad/plan.json --mode dry_run
python3 -m pto_agent cad apply     --file drawings/korpus2_plan_v1.dxf --plan out/cad/plan.json \
        --mode commit --confirm-by "Иванов И.И." --comment "Пометки к корректировке КС-2 подтверждаю"
python3 -m pto_agent cad diff   --before drawings/korpus2_plan_v1.dxf --after drawings/korpus2_plan_v2.dxf
python3 -m pto_agent cad takeoff --file drawings/korpus2_plan_v2.dxf --summary out/summary.json
python3 -m pto_agent cad render  --file drawings/korpus2_plan_v2.dxf --out out/cad/preview.png --panels

# MCP: stdio для клиентов, http для проверки руками (инспектор на /)
python3 -m pto_agent mcp --transport stdio
python3 -m pto_agent mcp --transport http --port 8765
```

Артефакты прогона: `out/cad/plan.json`, `out/cad/history.jsonl`, `out/cad/audit.jsonl`,
`out/cad/korpus2_plan_v2_scheme.dxf` + `.png` + `.manifest.json`, `out/cad/preview_sheet_and_zoom.png`.

## 3. Как это устроено

```
DXF ──► drawing.py ──► inventory / titleblock / takeoff
                │
                ├── template.py ──► validate_drawing  (слои, блоки, стили, высота текста, штамп, рамка)
                │
summary.json ───┴──► redline.py ──► операции (ADD_CLOUD / ADD_TEXT) + needs_human_decision
                                        │
                                  ops.py: validate_operations → apply_operations (dry_run | commit)
                                        │                       │
                                   diff.py (что изменилось)   audit.py + history.jsonl (версии, хэши)
                                        │
                                 mcp_server.py: 10 инструментов по JSON-RPC 2.0 (stdio / http)
```

| Модуль | Ответственность | Ключевое решение |
|---|---|---|
| `cad/drawing.py` | чтение DXF, инвентаризация, адресация объектов по handle | DWG не «делаем вид, что прочитали»: явная ошибка + инструкция (ODA File Converter) |
| `cad/template.py` | корпоративный шаблон `config/cad_template_corp_A.yaml` | проверки делятся на **блокирующие** и предупреждения; высота текста считается **в мм печати** (модель ÷ масштаб) |
| `cad/ops.py` | белый список из 7 операций, валидация, dry_run/commit | DELETE, MODIFY_LAYER, ROTATE, COPY, SCALE, ADD_RASTER — **отсутствуют в реестре**, поэтому отклоняются на валидации |
| `cad/diff.py` | сравнение двух состояний | diff строится по содержимому объектов, а не по «обещаниям» операций |
| `cad/redline.py` | расхождения КС-2 → пометки на чертеже | координаты берутся из габаритов объекта; уверенность < 0,7 → **решение человека**, а не операция |
| `cad/takeoff.py` | объёмы из блоков `ПОЗ_ОБЪЁМ` и сверка с актом | допуск ±5 % из шаблона; сравнение по шифру, затем по наименованию |
| `cad/render.py` | PNG-предпросмотр листа и фрагмента | подмена отсутствующих шрифтов и цвета 7 только при рендере — сам DXF не меняется |
| `cad/mcp_server.py` | MCP-сервер | commit через MCP без `confirm.by` возвращает ошибку инструмента и **не пишет файл** |

### Пять правил, которые нельзя обойти (и они проверены тестами)

1. **Агент не редактирует чертёж напрямую.** Только типизированные операции из белого списка; операция вне списка → отказ.
2. **Оформление неприкосновенно.** Слои `0`, `DEFPOINTS`, `ОС_РАМКА`, `ОС_ШТАМП` и вставки рамки/штампа защищены; поле штампа `ФИО` может заполнить только человек.
3. **Нет уверенности — нет операции.** Помеченные с `confidence < 0,7` уходят в `needs_human_decision` с причиной и предложенным действием.
4. **Признак изменения — diff, а не отчёт агента.** После применения считается фактический diff; отдельно контролируется потеря объектов при сохранении (требование ТЗ).
5. **Подпись и передача заказчику — только человеком.** `commit` без `--confirm-by` отклоняется; выпуск схемы фиксируется в журнале с хэшем версии.

## 4. Демо-прогон: что именно произошло

### 4.1 Проверка оформления (`corp-A/v4`)

| Замечание | Тип | Что заложено в чертеже |
|---|---|---|
| `OBJECTS_ON_PROTECTED_LAYER` | блокирует | линия на слое `0` |
| `TEXT_HEIGHT_BELOW_MIN` | блокирует | 3 текста высотой 200 мм в модели = 2,0 мм в печати при норме 2,5 мм |
| `TITLEBLOCK_INCOMPLETE` | блокирует | в штампе не заполнено обязательное поле `ШИФР` |
| `UNKNOWN_LAYER` | предупреждение | слой `МУСОР` вне шаблона |
| `UNKNOWN_BLOCK` | предупреждение | блок `УЗЕЛ_СТАРЫЙ` вне шаблона |
| `UNKNOWN_TEXT_STYLE` | предупреждение | стиль `ARIAL_OLD` вне шаблона |

Выпуск схемы: **запрещён** (код возврата 1) — до исправления оформления исполнительную схему не выдаём.

### 4.2 Пометки по расхождениям КС-2

Из `out/summary.json` (черновик акта) взяты 7 расхождений:

| Расхождение | Что сделал агент |
|---|---|
| `DUPLICATE` (плита) | облако вокруг блока объёма + пояснение «дубль записи в журнале: дублей 1» |
| `VOLUME_OVER_ESTIMATE` (плита 1240 > 1200) | пояснение во второй строке того же облака (одна пометка на объект) |
| `UNIT_MISMATCH` (стяжка: м² в смете, м³ в журнале) | облако + пояснение |
| `ALREADY_CLOSED` (трубы: 200 + 480 > 640) | облако + пояснение |
| `NOT_IN_ESTIMATE` (отмостка) | найдена по наименованию (уверенность 0,74) → пометка «нет в смете» |
| `VOLUME_OVER_ESTIMATE` и `MISSING_BACKING_DOCS` по фундаментным балкам | **позиции нет на чертеже** → 2 записи в `needs_human_decision` с причиной, а не «притянутая» пометка |

### 4.3 Применение и версия

- `dry_run`: 9 изменений, все на слое `ПОМЕТКИ`, **файл не записан** (хэш v1 не изменился).
- `commit` без подтверждения: отказ (`NO_HUMAN_CONFIRMATION`).
- `commit` с подтверждением: `drawings/korpus2_plan_v2.dxf`, объектов 31 → 40, потерь 0,
  запись в `out/cad/history.jsonl` (хэши до/после, состав операций, кто подтвердил) и в `out/cad/audit.jsonl` (хэш-цепочка).
- `diff v1 → v2`: +9 объектов на слое `ПОМЕТКИ`, изменённых и удалённых нет.

### 4.4 Сверка объёмов схемы с актом (±5 %)

| Шифр | На схеме | В акте | Δ | Вывод |
|---|---|---|---|---|
| ФЕР 06-01-001-01 | 1 240 м³ | 1 240 м³ | 0 % | сходится |
| ФЕР 08-02-001-01 | 1 180 м² | 1 180 м² | 0 % | сходится |
| ФЕР 12-01-034-02 | 900 м² | 900 м² | 0 % | сходится |
| ФЕР 16-02-003-01 | 440 м | 480 м | −8,3 % | **замечание**: в акте на 40 м больше, чем на схеме |
| ФЕР 11-01-011-01 | 210 м³ | 210 м³ (в смете м²) | — | несовпадение единиц |
| без шифра (отмостка) | 340 м² | — | — | работа есть на схеме, в смете/акте отсутствует |
| ФЕР 06-01-001-02 | нет на схеме | 390 м³ | — | объём предъявлен, схемой не подтверждён |

## 5. MCP-сервер

**Инструменты** (имена из ТЗ выделены):

| Инструмент | Что делает |
|---|---|
| **`get_drawing_info`** | единицы, слои, блоки, стили, штамп, объёмы на схеме |
| **`analyze_redline`** | расхождения → типизированные операции + `needs_human_decision` |
| **`validate_operations`** | проверка плана: белый список, слои, высота текста, лимиты, уверенность |
| **`apply_operations`** | `dry_run` (diff без записи) / `commit` (только с `confirm.by`) |
| **`export_scheme`** | выпуск схемы: DXF + PNG + паспорт выпуска (json) |
| `cad_validate_template` | проверка чертежа по корпоративному шаблону |
| `cad_takeoff` | объёмы схемы и их сверка с актом (±5 %) |
| `cad_diff` | сравнение двух версий чертежа |
| `cad_history` | журнал версий: хэши, операции, кто подтвердил |
| `cad_list_operations` | белый список операций и запрещённые типы |

**Транспорты.** `--transport stdio` — для MCP-клиентов (Claude Desktop, IDE, собственный агент);
`--transport http` — JSON-RPC на `POST /mcp` плюс страница-инспектор на `GET /` для проверки руками.

Пример обмена:

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"apply_operations","arguments":{
  "file_path":"drawings/korpus2_plan_v1.dxf","operations":[...],"mode":"dry_run"}}}
```

Ответ инструмента — MCP-контент `[{"type":"text","text":"<json>"}]`; при отказе (например, `commit` без подтверждения)
выставляется `isError: true`, а файл не создаётся — это проверено тестом.

## 6. Соответствие требованиям ТЗ

| Требование | Реализация | Статус |
|---|---|---|
| Поддержка DWG/DXF | DXF — чтение/запись через ezdxf; DWG — явный отказ с инструкцией конвертации и требованием сверки количества объектов | частично (конвертация — на стороне заказчика) |
| Корпоративные шаблоны (рамки, слои, блоки, шрифты) | `config/cad_template_corp_A.yaml`: 8 слоёв, белый список блоков, стили текста и размеров, поля штампа, масштаб, допуск ±5 % | реализовано |
| Headless-режим | ezdxf, без AutoCAD/COM; рендер предпросмотра через matplotlib | реализовано |
| Все изменения — с подтверждением человеком | `commit` без `confirm.by` → отказ; `dry_run` по умолчанию; журнал с хэшем версии | реализовано |
| Прозрачность каждого действия | diff по объектам, `out/cad/audit.jsonl` (хэш-цепочка), `history.jsonl` (версии и хэши) | реализовано |
| Типизированные операции, белый список | 7 разрешённых типов, 6 запрещённых (`DELETE`, `MODIFY_LAYER`, `ADD_RASTER`, `ROTATE`, `COPY`, `SCALE`) | реализовано |
| Объёмы схемы сопоставимы с КС-2 (±5 %) | `cad_takeoff` + правило `takeoff_vs_act_pct: 5` в шаблоне | реализовано |
| Связь с АОСР/ИД | источник каждой пометки — расхождение ПТО со ссылкой `discrepancies#N` | реализовано (связь с самим АОСР — этап 2) |
| PDF | нет: в сборке отсутствует PyMuPDF; выпуск PDF — через установку зависимости | не реализовано, зафиксировано честно |

## 7. Ограничения (честно)

- **Нет распознавания сканов и redline-картинок.** `analyze_redline` работает по уже найденным расхождениям и по подписям в DXF, а не по растровому скану с пометками. Vision-модель в контуре предусмотрена конфигом (`local-qwen-vl-32b`), но не подключена.
- **DWG не читается напрямую** — конвертация в DXF выполняется инструментом заказчика (ODA/LibreDWG). Проверка «количество объектов до/после» реализована для сохранения версии, но не для внешней конвертации.
- **PDF не формируется** — нужен PyMuPDF (или внешний рендер), добавим в поставку вместе с лицензионной проверкой.
- **Шрифты ГОСТ/ISOCPEUR в контейнере отсутствуют**, поэтому предпросмотр рендерится с подменой шрифтов (сам DXF не меняется). В контуре заказчика подставляются его корпоративные шрифты.
- **Геометрия демо-чертежа синтетическая**: плита 30 × 24 м, 6 машиночитаемых объёмов. Логика проверена, но не «обкатана» на реальном комплекте из 50 листов.

## 8. Следующий этап

1. Реальный комплект: 3–5 листов одного объекта, корпоративный шаблон заказчика, прогон `validate` + `takeoff` и сверка с ручной проверкой ПТО.
2. Распознавание сканов redline (OCR + vision через локальную VL-модель) → те же типизированные операции, но с bbox и `confidence`.
3. PDF-выпуск и штамп «В производство работ» с ЭП; пакетная обработка листов.
4. MCP-инструменты ПТО (не только CAD): сверка КС-2, комплектность ИД, нормативка — в один сервер, чтобы клиент видел весь набор.
5. Хранение версий в БД (`db/schema.sql`, таблица CAD-операций уже описана) вместо файлов.
