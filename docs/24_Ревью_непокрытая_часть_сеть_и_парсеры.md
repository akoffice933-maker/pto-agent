Порядок работы тот же: **воспроизвести → записать тест → исправить**. Сначала я показывал

## 1. Что было не так (воспроизведено)

### 1.1. LLM: запрос уходил на метаданные облака

```python
PTO_LLM_BASE_URL=http://169.254.169.254
llm.chat("Пришли смету по объекту", data_class="commercial_secret")
→ запрос ушёл на: http://169.254.169.254/v1/chat/completions
```

Проверка в коде была такой: «если адрес начинается на `http://10.` — считаем недоступным,
иначе идём». То есть отсекались как раз внутренние адреса, а `127.0.0.1`, `169.254.169.254`
(метаданные инстанса: токены AWS/GCP/Яндекс.Облака) и любой внешний хост — проходили.
Внешний хост принимался и по открытому `http`.

### 1.2. LLM: класс данных проверялся только на бумаге

`route()` вычислял `blocked_by_policy`, но `chat()` это поле игнорировал: достаточно передать
`provider_id` явно, и «коммерческая тайна» уходила в облако. Политика 152-ФЗ была описана в
конфиге, но не исполнялась в момент вызова.

### 1.3. Vision: логика проверки адреса перевёрнута

| Адрес | Было | Должно быть |
|---|---|---|
| `http://10.20.0.12:8000` (свой контур) | «недоступен» | недоступен из разработки, доступен в контуре |
| `http://169.254.169.254/latest/meta-data` | **разрешён** | запрещён всегда |
| `http://127.0.0.1:8080` | разрешён | локальный — только осознанно |
| `https://attacker.example.com/v1` | разрешён | разрешён (адрес нельзя угадать), но данные — по политике |

Плюс: изображение листа проектной документации уходило провайдеру независимо от его
резидентности — поле `residency` в конфиге было справочным.

### 1.4. 1С: схема не проверялась, POST повторялся без ключа идемпотентности

* `OneCHttpClient("file:///etc")` — создавался успешно, `urllib` умеет `file://`;
* `http://1c.example.com` с basic-auth — принимался (пароль и данные открытым текстом);
* при сетевой ошибке **POST повторялся** до `retries+1` раз даже без `Idempotency-Key` —
  то есть «сеть моргнула» превращалось в два документа КС-2 в 1С;
* в текст исключения попадали первые 500 символов тела ответа 1С (внутренние адреса, имена
  баз) и полный URL;
* ответ читался целиком (`r.read()`) — сервер на 2 ГБ ронял процесс;
* переадресация: `urllib` переносит заголовки на новый адрес, то есть редирект уводил
  `Authorization` чужому хосту.

### 1.5. Парсеры XLSX: атака на память и «тихие нули»

* `load_workbook(...)` без `read_only` + `list(ws.iter_rows(...))` — книга грузилась целиком;
* `_num("десять")` → `0.0`: строка сметы с испорченным количеством давала нулевую сумму
  **без единого предупреждения**;
* `_date("не дата")` → `date.today()`: журнал работ получал **выдуманную сегодняшнюю дату**.

Это прямо противоречит правилу проекта «никаких выдуманных чисел»: ноль и сегодняшнее число
выглядели как данные.

### 1.6. CSV: формула из чужой сметы исполнялась в Excel

Наименование позиции вида `=cmd|' /C calc'!A0` записывалось в `discrepancies.csv` и в
выгрузку для 1С как есть: Excel/1С исполняет ячейку, начинающуюся с `=`, `+`, `-`, `@`.

## 2. Что сделано

### 2.1. Новый модуль `pto_agent/netguard.py`

Одно место, где решается «куда можно идти и сколько можно прочитать»:

| Проверка | Правило |
|---|---|
| Схема | только `http`/`https`; `file://`, `ftp://`, `gopher://` — отказ |
| Метаданные облака | `169.254.169.254`, `169.254.170.2`, `100.100.100.200`, `fd00:ec2::254`, `metadata.google.internal` — запрет всегда |
| Открытый http | для внешнего хоста нужен `https`; для внутреннего контура и localhost — можно (это норма для 1С и локальной модели) |
| Переадресация | только в пределах того же хоста, иначе `CROSS_HOST_REDIRECT` |
| Размер ответа | чтение порциями с жёстким пределом (10 МБ для сервисов, 4 МБ для модели), без доверия к `Content-Length` |
| Текст ошибок | `public_message()` убирает URL и учётные данные — клиент видит `<адрес>`, подробности идут в stderr |

Подключено во всех трёх сетевых местах, а не в одном:

* **`llm.chat_ex`** — проверка адреса, ограничение размера, политика класса данных
  (`check_provider_policy`) **в момент вызова**; для «коммерческой тайны» и персональных
  данных запрещено подменять адрес переменной `PTO_LLM_BASE_URL` — только конфиг;
* **`cad/vision/providers.py`** — `_base_is_reachable_shape` больше не перевёрнута, адрес
  провайдера валидируется перед вызовом, ответ читается ограниченно, изображение с классом
  данных «коммерческая тайна»/«персональные» не уходит провайдеру с резидентностью вне
  контура;
* **`integrations/one_c_http.py`** — схема и хост проверяются в конструкторе; POST без
  `Idempotency-Key` не повторяется; тело ответа в ошибке очищается от паролей и адресов;
  размер ответа ограничен; редирект на другой хост прерывается.

### 2.2. Парсеры: пределы и явные замечания

```python
MAX_FILE_BYTES = 25 МБ     MAX_ROWS = 200 000     MAX_SHEETS = 20
```

* чтение потоковое (`read_only=True`, `keep_links=False`), книга закрывается в `finally`;
* превышение — `WorkbookTooLarge` с понятным текстом, а не падение по памяти;
* `_parse_number` и `_parse_date` возвращают `None` там, где данные битые;
* новые читатели `read_estimate_ex`, `read_journal_ex`, `read_closed_ex` возвращают
  `(записи, problems)`: «количество не число», «цена не число», «дата не распознана» — с
  номером строки, сырым значением и следствием («позиция вошла с нулём — сумма по ней не
  посчитана», «строка журнала пропущена, а не отнесена к сегодняшнему дню»);
* CLI `run` печатает замечания и пишет их в журнал аудита (`documents.read`), а при
  `WorkbookTooLarge` останавливается с кодом 2;
* старые функции оставлены как обёртки — обратная совместимость не ломается.

### 2.3. CSV: экранирование формул

`csv_safe()` в `netguard` применён в двух местах, где пишется CSV: `export_discrepancies_csv`
(расхождения) и выгрузка для 1С (`one_c._write_csv`). Значения, начинающиеся с `=`, `+`, `-`,
`@`, табуляции или `\r`, получают апостроф; числа не трогаются.

## 4. Что осознанно не сделано

1. **Белый список доменов для LLM/vision.** Сейчас разрешён любой `https`-хост: адрес
   провайдера — это настройка администратора, и угадать «плохой» домен нельзя. Если нужно
   жёстче — добавляется список `allowed_hosts` в конфиг провайдера (полчаса работы), но это
   уже политика эксплуатации, а не дефект кода.
2. **Проверка TLS-пиннинга.** Используется стандартная проверка сертификата и имени хоста из
   `ssl`; пиннинг сертификата для 1С на предприятии — по требованию службы безопасности.
3. **Ограничения на формулы внутри XLSX.** `data_only=True` не вычисляет формулы (читает
   кэш), но макросы не блокируются на уровне `openpyxl` — файлы `.xlsm` лучше не принимать
   вовсе; в матрице рисков это записано.
4. **`reconcile`/`impact` на `Decimal`** — из прошлого списка (п. 5.6 документа 23),
   не входило в этот круг.
5. **SSRF через прокси-переменные окружения.** `ProxyHandler` берёт `HTTP_PROXY` из среды; в
   контуре заказчика это штатно, но при недоверенной среде переменные надо чистить. Отмечено,
   не менял.
