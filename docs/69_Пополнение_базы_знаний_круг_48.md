# Круг 48. Пополнение базы знаний из внешних источников

Запрос: нормативная база почти пуста, нет ни одного документа по электромонтажу в статусе
«загружен целиком», нет ФЕР/ТЕР, нет реестра отчётности и данных заказчика. Ниже — что реально
взято, откуда именно, в каком виде лежит в репозитории и что взять было неоткуда.

**Статусы не выдуманы.** В источнике `status: active` стоял только у СП 16.13330.2017; остальные
пришли как `unknown`, и такая база их просто не цитирует. Статус подтверждён внешней сверкой
(приказы, даты ввода, изменения) и записан в front-matter каждого файла полями
`status_checked_at`, `status_source`, `status_note` — вместе с оговоркой, что **тексты изменений
в базе не сверялись**: загружены редакции из источника, а не официальные тексты с изменениями.
Если нужна юридическая точность — сверять по официальному опубликованию.

## 2. ФЕР: 51 897 расценок из официальных открытых данных ФГИС ЦС

Не с GitHub-копии, а из первоисточника — открытых данных Минстроя России на портале ФГИС ЦС:

```
GET https://fgiscs.minstroyrf.ru/api/OpenData            → 15 наборов
GET https://fgiscs.minstroyrf.ru/api/OpenData/3          → паспорт ФСНБ-2020 (7707082071-fsnbfer)
GET https://fgiscs.minstroyrf.ru/api/values/GetFileContent/<uuid> → zip (13 МБ)
```

В архиве ФСНБ-2020 (доп. № 9, приказы Минстроя России от 20.12.2021 № 961/пр, 962/пр,
действует с 01.02.2022) — XML `ФЕР.xml`, `ФЕРм.xml`, `ФЕРр.xml`, `ФЕРп.xml`, `ФЕРмр.xml`,
`ФССЦ.xml`, `ФСЭМ.xml`. Импорт: `scripts/import_fsnb.py`, преобразование в выгрузку цен:
`scripts/fasnb_to_prices.py`, загрузка в базу агента: `python3 -m pto_agent prices import`.

| ФЕРм (монтаж оборудования) | 18 696 | 08-02-141-01 Кабель до 35 кВ в готовых траншеях, масса 1 м до 1 кг — 242,91 ₽/100 м |

Что лежит в репозитории (`data/fsnb/`, 2,7 МБ):

* `fer2020.csv.gz` — расценка, наименование, единица, цена, ФОТ, машины, материалы,
  машинист, НР, СП, сборник;
* `fsbc2022.csv.gz` — **45 847 ресурсов** ресурсного каталога ФСБЦ-2022 (материалы и оборудование):
  код, наименование, единица, цена, оптовая цена. Пример: `21.1.06.07-0021` кабель АВВГ 1×2,5 — 7 560,76 ₽/1000 м;
* `data/prices_fsnb/` — версия цен агента (51 897 позиций, digest `1bdd4007fcd6743c`),
  которую читает `prices.lookup`.

Три честные оговорки:

1. **Это базисный уровень цен 01.01.2000**, а не текущие рыночные цены. Чтобы получить
   сметную стоимость, нужны индексы Минстроя — в базе их нет, и подставлять вместо них
   «похожую» цену агент не будет.
2. **ТЕР нет.** Территориальные расценки в открытых данных ФГИС ЦС не публикуются:
   реестр ТЕР есть (разделы 6 и 7), а сами сборники — на сайтах региональных центров
   ценообразования, часто в PDF и с условиями использования. Скачать их автоматически
   нельзя, и это не «недоработка в один клик».
3. **Код расценки в базе цен — составной**: `ФЕР/08-01-001-01`, `ФЕРм/08-02-141-01`.
   Без префикса базы код `08-02-001-01` указывает одновременно на две разные расценки
   (строительные работы и монтаж оборудования) — это ловушка, на которую я наступил
   при первом импорте и исправил.

  ГОСТ 27751 — 27 → 95.
* `scripts/import_pue.py` (новый) — PDF ПУЭ → пункты с номерами страниц.
* `scripts/import_fsnb.py`, `scripts/fasnb_to_prices.py` (новые) — ФЕР/ФСБЦ из XML ФГИС ЦС.
* `pto_agent/norms.py` — исправлены две ошибки в `NormIndex.ask`:
  (1) падение `TypeError: 'Clause' object is not subscriptable` при пустом результате
  (`hits` — список `Clause`, а не словарей) — то есть любой вопрос без ответа ронял CLI;
  (2) цитата длиннее 400 символов обрезалась с «…», и проверка дословности искала в тексте
  многоточие, которого там нет, — из-за этого **любой длинный пункт блокировался**
  как «цитата не прошла проверку». Теперь проверяется показанная часть без «…»
  (поле `truncated` говорит, что цитата сокращена).
  Плюс `README.md` больше не грузится как нормативный документ.
* `pto_agent/prices.py` — выгрузка цен читается из `.csv.gz`, а версия тяжелее 5 МБ
  сохраняется как `.json.gz` (30 МБ JSON → 1,2 МБ). Без этого ФСНБ физически не помещалась
  в репозиторий.
* `data/reference/takeoff_map_fer.json` — 4 правила «элемент → код расценки ФЕРм»
  (кабель в траншее, кабель из сшитого полиэтилена, розетки, распределительный шкаф).
  Ведомость по ним даёт базисные цены 2000 года — это видно в наименовании и в источнике.

## 4. Чего взять неоткуда (и это не «сделаем позже»)

| пробел | почему не закрыт |
|---|---|
| **ТЕР** (территориальные расценки) | в открытых данных ФГИС ЦС только федеральная база; сборники ТЕР публикуются региональными центрами ценообразования (PDF/DOC, свои условия использования). Легального машиночитаемого источника нет |
| **Индексы пересчёта** в текущий уровень цен | публикуются письмами Минстроя (PDF, ежеквартально). Письма можно внести в базу цен, но это ручной импорт; подставлять индексы «из памяти» я не стал |
| **Реестр ранее сданной отчётности заказчика** | это данные конкретной организации (акты, КС-2, реестры). Во внешних источниках их нет по определению: доступ даёт только заказчик. Механика реестра в системе есть (`cumulative`, `statements`), но пустая — заполняется загруженными документами объекта |
| **Данные заказчика (объект, договоры, лимиты)** | то же: персональные/коммерческие данные, внешнего источника не существует |
| **Официальные тексты СП с изменениями** | в источнике `norm-md-db` — редакции без изменений; тексты изменений нужно догружать из официальных публикаций (это следующая работа, а не «уже сделано») |

## 5. Чем проверено

```
python3 -m pytest -q                       → 1696 passed, 78 skipped
python3 -m pto_agent norms "требования к электропроводкам в пожароопасных зонах" --data data/demo
python3 -m pto_agent prices --out data/prices_fsnb lookup --code "ФЕРм/08-02-141-01"
python3 -m pto_agent takeoff draft --boq … --prices-dir data/prices_fsnb --map data/reference/takeoff_map_fer.json
```

Изменены три существующих теста — и это не «подгонка под ответ»:

* два теста ждали, что ПУЭ 1.8.37 будет «подтверждён фрагментом». Теперь ПУЭ загружен целиком,
  поэтому статус — `verified`; сценарий фрагмента проверяется на отдельном каталоге с одним
  фрагментарным документом (раньше он проверялся «случайно», на реальной неполной базе).
* третий тест искал отсутствующий пункт «4.2.1» — в полном ПУЭ такой пункт есть (глава 4.2,
  нумерация до 4.2.120). Взят пункт 4.2.999, которого действительно нет.

## 6. Пример: что теперь отвечает агент по электромонтажу

```
$ python3 -m pto_agent norms "требования к электропроводкам в пожароопасных зонах" --data data
→ ambiguous, ПУЭ п. 7.4.17 (verified: true)
  «Электрооборудование переносного электрифицированного инструмента в пожароопасных зонах
   любого класса должно быть со степенью защиты оболочки не менее IP44…»
  ПУЭ п. 7.4.35 (verified: true) — «Переносные светильники… не менее IP54…»

$ python3 -m pto_agent norms "испытание электропроводок сопротивлением изоляции" --data data
→ ambiguous, ПУЭ п. 1.8.28 и п. 1.8.29 (verified: true)

$ python3 -m pto_agent prices --out data/prices_fsnb lookup --code "ФЕРм/08-02-141-01"
→ 242,91 ₽ за 100 м · ФЕРм-2020 · базис 01.01.2000 · digest 1bdd4007fcd6743c
```

Ответ `ambiguous` — это не ошибка, а честный статус: в ПУЭ несколько пунктов по теме,
и агент показывает два ближайших вместо того, чтобы выбрать один «за инженера».
