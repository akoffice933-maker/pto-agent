# Книга продаж, нумерация счетов-фактур и вычет НДС с выданных авансов

Документ закрывает две дырки, названные в круге 32:

1. **вычет НДС с авансов, выданных поставщикам, не попадал в декларацию** — журнал знал про
   вычет больше, чем декларация;
2. **не было реестра счетов-фактур и книги продаж** — бланк СФ печатался с пустым номером,
   а суммы декларации считались прямо из оборотов.

Здесь же — три моих ошибки, найденные при этой работе.

## 1. Ошибки круга 32, найденные в круге 33

| Ошибка | Как проявилась | Что исправлено |
|---|---|---|
| в блоке `issued` были перепутаны стороны 76.ВА | вычет 2 200 000 ₽ показывался как 0, а восстановление — как 2 200 000. Тест круга 32 проверял только имя счёта и мимо этого прошёл | 76.ВА — активный счёт: вычет идёт в **кредит** (`Дт 68.02 Кт 76.ВА`), восстановление в **дебет**. Тест `test_issued_block_sides_are_not_swapped` ловит именно это |
| вычет по выданным авансам не был строкой декларации | `vat_return` не вычитал его из налога: «к уплате» было больше на 2 200 000 ₽ | строка «НДС с авансов, выданных поставщикам» + `vat_on_issued_advances` в итогах, вычет уменьшает `payable` |
| ставка при восстановлении НДС искалась только в документе зачёта | зачёт аванса (`Дт 60.01 Кт 60.02`) не содержит ставки, поэтому восстановление не считалось вовсе | ставка берётся из документа **самого аванса** по связке «контрагент + договор»; нет ставки нигде — требование, а не проводка |

## 2. Что теперь считается в декларации

```
начислено  = 90.03 (реализация)
           + НДС с авансов полученных (по 62.02, ставка на дату аванса)
           + восстановлено НДС с выданных авансов (Дт 76.ВА Кт 68.02)
к вычету   = прочие вычеты (19.03 и др., из Дт 68.02 за вычетом авансовых)
           + вычет НДС с авансов полученных при зачёте (проводки зачёта 62.02)
           + вычет НДС с авансов выданных (Кт 76.ВА — Дт 68.02 Кт 76.ВА)
к уплате   = начислено − к вычету
```

Сверки, которые идут сами:

* `VAT_MISMATCH` — Кт 68.02 не равен сумме начислений (реализация + авансы + восстановление);
* `VAT_ADVANCE_NOT_POSTED` — авансовый НДС посчитан, но на 76.АВ его нет;
* предупреждение «вычет по выданному авансу без счёта-фактуры» — пока реестр не заполнен.

На сценарии круга 33 (аванс 12 200 000 ₽ поставщику, ставка 22 % в заявке):
вычет **2 200 000 ₽**, «к уплате» **−2 200 000 ₽** (возмещение — отдельная строка и повод
для подтверждения), при зачёте половины аванса восстановлено **1 100 000 ₽**.

## 3. Нумерация счетов-фактур

Правила — в `data/reference/invoice_rules.json`, а не в коде: нумерация — решение организации.

| Что | Значение | Источник |
|---|---|---|
| порядок | сквозная, в хронологическом порядке выставления | п. 3 раздела II прил. 1 к постановлению Правительства РФ от 26.12.2011 № 1137 |
| сброс | с 1 января — снова с 1 | там же |
| префиксы | отгрузка ``, аванс ``, корректировочный `К` | решение организации |
| переиспользование номера | **запрещено**, даже для аннулированного документа | иначе в книге окажутся два разных документа с одним номером |
| срок выставления | 5 календарных дней со дня отгрузки или получения аванса | п. 3 ст. 168 НК РФ |
| дата СФ раньше основания | отказ `INVOICE_DATE_BEFORE_BASE` | документ не может появиться до события |

Ставка в счёте-фактуре **не подставляется**: нет ставки — нет документа (`INVOICE_NO_RATE` в
«что запросить»). Нулевая ставка регистрируется, но с предупреждением, что нужна норма
(ст. 149 или ст. 164 НК РФ): нулевая ставка и забытый налог — разные вещи.

Команды:

```
python3 -m pto_agent invoices rules                 # правила и «не сделано»
python3 -m pto_agent invoices next 2026-10          # следующий номер
python3 -m pto_agent invoices auto 2026-10 --dry-run # что было бы выставлено
python3 -m pto_agent invoices auto 2026-10          # выставить из журнала
python3 -m pto_agent invoices sales-book 2026-10    # книга продаж и сверка
```

Экран: блок «Книга продаж» на `/taxes?period=…` с таблицей документов, разницей с журналом и
кнопкой «Выставить счета-фактуры» (маршрут `POST /taxes/invoices`, с CSRF и записью в аудит).

## 4. Книга продаж

Строится **из реестра счетов-фактур**, а не из оборотов: счёт-фактура — это документ, по
которому покупатель заявляет вычет, поэтому книга идёт от документов.

| Вид | Откуда берётся |
|---|---|
| отгрузка | подписанный акт (`act_signed`): база = 90.01 − 90.03, ставка восстанавливается из акта |
| аванс | поступление на 62.02: НДС = сумма × ставка / (100 + ставка) |

Затем НДС по книге сверяется с начислением в журнале. Если акт подписан, а счёт-фактура не
выставлен, книга **меньше** начисленного НДС на эту сумму — и это `SALES_BOOK_MISMATCH` с
числом, а не подстановка суммы из журнала.

Важное следствие: если акт содержит НДС по устаревшей ставке (сценарий 20 % вместо 22 %),
счёт-фактура **повторяет акт** (`rate = 20 %`), а не «исправляет» его законной ставкой.
Расхождение ставки приходит из `vat_return` как `VAT_RATE_STALE`. Книга продаж не место, где
исправляют первичку: для этого есть корректировочный счёт-фактура.

## 6. Не сделано (и почему)

1. **Книга покупок.** В контуре нет реестра входящих счетов-фактур: вычет по 19.03 считается по
   проводкам, а не по документам. Без парного реестра книга покупок была бы списком сумм без
   оснований.
2. **Корректировочные счета-фактуры.** Префикс `К` зарезервирован, но регистрация исправлений
   (корректировка КС-2, УПД) не сделана — значит и исправить книгу продаж контур пока не умеет.
3. **Журнал учёта полученных и выставленных счетов-фактур** (посредники, комитенты) — не ведётся:
   в контуре нет посреднических схем.
4. **Выгрузка книг в формате ФНС.** XML/таблицы собираются в пространстве имён контура;
   сверки со схемой нет — XSD недоступен из песочницы.
5. **Графы книги продаж помечены «на проверку»:** форма книги менялась вместе с формой СФ
   (приказ ФНС от 18.12.2025 № ЕД-7-3/1227@). Состав графов перед сдачей сверять с действующей
   редакцией — это записано и в справочнике (`sales_book.verify`), и на экране.
6. **Номера строк раздела 3 декларации** по-прежнему не проставлены для двух новых строк: в
   редакции формы 2026 года они не подтверждены, поэтому строки названы словами и помечены
   «на проверку». Выдуманный код строки хуже его отсутствия.
7. **Демо-контур без подписанных актов**: книга продаж на экране пустая, кнопка «выставить»
   ничего не создаёт. Это состояние данных, а не отсутствие функции — сценарий с актами
   проверяется в `check_invoices.py` и тестах.
