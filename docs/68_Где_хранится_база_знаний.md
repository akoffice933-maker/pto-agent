# Круг 47. Где в проекте хранится база знаний

Вопрос по делу: «база знаний» в этом контуре — не одно место, а **шесть слоёв с разным статусом
достоверности**. Их важно различать: смешав справочник, демо-данные и нормативный первоисточник,
легко получить ответ, который выглядит проверенным, но ничем не подтверждён.

| слой | где лежит | что внутри | статус |
|---|---|---|---|
| 1. Нормативная база (RAG) | `data/norms/` и `data/demo/norms/` | тексты документов по пунктам (Markdown с front-matter) | первоисточник, цитата дословная |
| 2. Справочники правил | `data/reference/*.json` (29 файлов, 480 КБ) | нормы права и правила учёта в машинном виде, у каждого поле `source` | вторичный, со ссылкой на документ |
| 3. Цены ресурсов | `data/prices_skc_adler/`, `data/demo/prices/`, `data/demo/prices_kr1/`, `out/.../prices_store/` | версии базы цен: код ресурса, цена, НДС, регион, дата, digest | версионный, с отпечатком |
| 4. Демо-данные объекта | `data/demo/*` (37 разделов) | смета, журнал работ, акты, склад, зарплата, отчётность | демонстрация механик, **не** данные заказчика |
| 5. Документы объекта | `uploads/`, `.github/tz/` | ТЗ, скрипт ролика; PDF, из которого берутся объёмы | входной документ |
| 6. Описание системы | `docs/*.md` (108 файлов), `README.md` | что сделано, чем проверено, чего нет | документация, не источник цифр |

## 1. Нормативная база — `data/norms/`

Один `.md` на документ, пункты — заголовки `## <номер>`:

```
---
designation: СП 63.13330.2018
title: Бетонные и железобетонные конструкции. Основные положения
kind: СП
edition: с Изменением № 1
status: active            # active | fragment
effective_from: 2019-06-20
version: 3
source: Минстрой России
---
# СП 63.13330.2018
## 10.3.3
Для сборных элементов минимальная толщина защитного слоя бетона принимается равной 15 мм…
```

Что загружено сейчас:

* `data/norms/pue_7_1_8.md` — ПУЭ, 7-е изд., пп. 1.8.37 и 1.8.39, **фрагмент** (`status: fragment`);
* `data/demo/norms/` — СП 63.13330.2018, СП 48.13330.2019, СП 70.13330.2012 (демо-набор для прогонов).

Поиск — `pto_agent/norms.py`: BM25 по пунктам + **обязательная сверка цитаты** (`cite_verify`).
Ответ без дословной цитаты из указанного пункта указанной редакции не выдаётся: три состояния
`answer` / `not_found` / `ambiguous`. Проверка: `python3 -m pto_agent norms "…" --data data/demo`.

## 2. Справочники правил — `data/reference/*.json`

Здесь машинные правила, по которым контур считает и отказывает. Каждый файл содержит поле
`source` (или `sources`) со ссылкой на документ-основание и, где уместно, `not_implemented`.

| файл | что задаёт |
|---|---|
| `chart_of_accounts_94n.json` | план счетов (приказ № 94н), субсчета, забалансовые |
| `posting_rules.json` | правило «документ → проводка» (какой счёт, какая сторона, что минус) |
| `financial_statements_fsbu4.json` | форма баланса и ОФР по ФСБУ 4/2023: коды, счета, `why_empty` |
| `tax_rates.json` | ставки НДС/налога на прибыль, сроки, региональная часть |
| `vat_declaration_sections.json`, `vat_sections.json`, `vat_operation_codes.json` | разделы декларации, правило 5 %, коды операций |
| `invoice_rules.json` | счета-фактуры, книги продаж/покупок, корректировки |
| `payroll_rules.json`, `withholdings_rules.json` | НДФЛ, вычеты, взносы, МРОТ, пределы удержаний 20/50/70 % |
| `treasury_rules.json` | казначейство, очерёдность платежей, БДДС |
| `accounting_policy.json` | учётная политика контура |
| `year_close_rules.json` | порядок закрытия года (94, 96, 97, реформация 99 → 84) |
| `property_benefits.json` | льготы по имуществу: применяются только с подтверждённым основанием |
| `rbac.json`, `users.json` | роли, права, действия, демо-логины |
| `work_type_requirements.json` | матрица «вид работ → какие документы нужны» |
| `quality_docs.json` | виды документов качества и их псевдонимы |
| `takeoff_map*.json` | словарь «элемент ведомости → код ресурса в базе цен» |
| `fns_xml_profile.json`, `pdf_profiles.json` | профили XML ФНС и разбора PDF |
| `platform_oss.json`, `tax_edo_oss.json`, `tk_ppr_oss.json`, `asbuilt_tools.json`, `analogue_projects.json`, `takeoff_oss.json` | реестры опенсорса: лицензии, покрытие задач, чего нет |
| `analogue_projects.json` | проекты-аналоги для сравнения |

## 3. Цены — версии, а не «текущий прайс»

База цен устроена как **версии с датой и отпечатком**: `prices_<дата>-<источник>-<регион>.json`
плюс `index.json`. В каждой строке ведомости лежит `price_version` и `price_digest`, поэтому любую
сумму можно пересчитать и доказать, из какой версии она взята.

```
data/prices_skc_adler/                     # демо-ставки по объекту СКС «Адлер»
data/demo/prices/                          # выгрузки ФГИС ЦС (демо)
data/demo/prices_kr1/                      # выгрузка для прогона по ведомости КР
out/<прогон>/prices_store/                 # то, что собрано в конкретном прогоне
```

Импорт: `python3 -m pto_agent prices import --file … --source … --date …`.

## 4. Демо-данные — `data/demo/`

37 каталогов: `acts`, `journals`, `consumption`, `stock`, `payroll`, `treasury`, `accounting`,
`year_close`, `monthly`, `pack`, `quality_docs`, `docflow`, `correspondence`, `norms`, `prices`…
Это **демонстрация механик** и данные специально вымышленного объекта «ЖК Северный, корпус 2».
Ни один отчёт контура не выдаёт их за данные заказчика — в отчётах это сказано словами.

## 5. Документы объекта — `uploads/`, `.github/tz/`

`uploads/ТЗ Адлер.pdf` — ТЗ, по которому шёл прогон круга 46; `.github/tz/ТЗ_Адлер.pdf` — его копия
для шага CI, чтобы проверка не зависела от загрузок пользователя. Объёмы берутся только отсюда,
каждая строка ведомости помнит `source` вида «стр. 2, строка 64».

## 6. Описание системы — `docs/`

108 файлов `docs/NN_*.md` + строки в `README.md`: что сделано в круге, чем проверено, что не сделано.
Это документация, а **не** источник цифр: если цифра есть в `docs`, но её нет в данных или в
первоисточнике, она считается непроверенной.

## Чего в базе знаний нет (и это видно на экране)

* нормативная база почти пуста: **3 документа + один фрагмент ПУЭ** — этого мало для настоящей
  работы; каждая ссылка, которой нет в базе, помечается `doc_missing`, а не «неверна»;
* нет ни одного документа в статусе «загружен целиком» по электромонтажу (ПУЭ — фрагмент);
* ФЕР/ТЕР-расценок нет: цены — демо-ставки и демо-выгрузки ФГИС ЦС;
* нет реестра ранее сданной отчётности и нет данных заказчика — только демо-объект.

Проверка, что база знаний отвечает и **отказывается** отвечать:
`python3 -m pto_agent norms "…" --data data/demo` (три состояния ответа), `scripts/check_takeoff_oss.py`
(реестры опенсорса), `scripts/check_tz_tables.py` (объёмы из документа).
