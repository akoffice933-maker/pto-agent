# Сводка проверки: что проверено, что осталось, где нужен человек

К этому шагу у агента было пять источников правды: сверка КС-2 (`out/summary.json`), выпуск
со сканов (`out/cad/batch/batch_summary.json`), план правок чертежа (`out/cad/plan.json`),
деньги под риском (`out/cad/impact/impact.json`) и реестр актов (`data/demo/acts/acts.json`).
Каждый отвечал на свой вопрос — и инженер, глядя на пять файлов, всё равно не видел главного:
**можно подписывать или нет и что именно от него требуется**.

`review` собирает всё в один ответ: **что проверено**, **что осталось**, **где нужно решение
человека**, **сколько денег под риском** и **можно ли подписывать**.

## Как пользоваться

```bash
python3 -m pto_agent review                       # все артефакты по умолчанию
python3 -m pto_agent review --batch out/cad/batch/batch_summary.json \\
        --impact out/cad/impact/impact.json --out out/review
# отчёт: out/review/review.md (для человека) и out/review/review.json (для машины)
```

Через MCP — инструмент `review_summary` (16-й):

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call",
 "params":{"name":"review_summary","arguments":{"format":"markdown"}}}
```

`format: "json"` (по умолчанию) отдаёт структуру, `"markdown"` — готовый текст сводки:
удобно вставить в письмо или протокол совещания.

## Что внутри ответа

| Раздел | Смысл |
|---|---|
| `verdict` | `ready` / `needs_review` / `blocked` / `no_data`, флаг `can_sign`, одна строка-резюме |
| `checked` | 5 проверок: `ok` / `warning` / `fail` / **`skipped`** с источником и деталями |
| `decisions` | вопросы человеку: `question`, `why`, `action`, `source`, приоритет, `count` для сгруппированных |
| `open_items` | что осталось открытым: неподтверждённая калибровка, кеш, позиции без цены |
| `money` | к предъявлению, заблокировано, под риском, позиций без оценки |
| `next_steps` | что делать дальше — из тех же данных, без домыслов |

## Правила вердикта

| Условие | Вердикт | Подпись |
|---|---|---|
| есть блокирующие вопросы (критичное расхождение, нераспознанный лист, блокирующее нарушение шаблона) или проваленная проверка | `blocked` | нет |
| блокирующих нет, но есть важные вопросы, предупреждения или **пропущенные проверки** | `needs_review` | да, с оговорками |
| всё проверено, замечаний нет | `ready` | да |
| ни один артефакт не найден | `no_data` | нет |

Два принципа, которые важнее красоты отчёта:

1. **Пропуск — не «ок».** Нет сводки выпуска → проверка `skipped` с причиной, вердикт не может
   быть `ready`, в `next_steps` появляется «дособрать артефакты».
2. **«Не оценено» ≠ 0 ₽.** Позиция без цены не попадает в суммы, но попадает в `open_items`
   с действием «дозаполнить цены».

## Как это выглядит на демо-данных

```
Вердикт:   blocked · подпись невозможна
Подписывать нельзя: блокирующих вопросов 5, провалено проверок 1 из 4
  ✗ Сверка КС-2 с журналом и сметой: позиций 8, расхождений 7 (критичных 5)
  ! Выпуск со сканов (redline): листов 40 (ошибок 0), пометок 205, конфликтов с ПТО 43
  ! Деньги под риском: под риском 1 850 000.00 ₽ (5.42 % акта)
  ✓ Портфель актов и покрытие проверкой: актов 3, проверено 3
  · Чертёж: шаблон и план правок: нет плана операций — чертёж не проверялся
```

Деньги в сводке: к предъявлению 34 106 600 ₽, заблокировано 12 835 600 ₽, под риском
1 850 000 ₽ (5,42 % акта). Каждая цифра пришла из своего артефакта и в `review.json` рядом
лежит признак, откуда она взята.

## Почему вопросы сгруппированы

На выпуске 40 листов бывает 49 пометок без текста и 43 конфликта — если вывалить их списком,
сводку не прочитают. Поэтому решения группируются по причине: «пометки без текста — ещё 48
похожих (49 всего)», источник — листы, где они встретились, действие — одно. Полный перечень
остаётся в `review.json`, а в `review.md` печатаются первые 25 пунктов с явной пометкой
«…и ещё N».

## Проверено тестами

`tests/test_review.py` — 18 тестов: вердикты (`no_data` вместо «всё ок» при пустом входе),
блокировка по критичному расхождению и по нераспознанному листу, `needs_review` без блокировки,
пропущенная проверка с причиной, «не оценено» в открытых пунктах, агрегация денег, блокирующие
нарушения шаблона, порядок «сначала блокирующие», группировка вопросов выпуска, обязательные
разделы markdown, запись отчётов, CLI и оба режима MCP-инструмента.
