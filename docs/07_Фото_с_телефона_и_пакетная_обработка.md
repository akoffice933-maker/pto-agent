## 2. Фото с телефона: зачем нужна перспектива

Скан с планшета привязывается к чертежу масштабом и сдвигом: лист на нём — прямоугольник.
Фото с телефона снято под углом, и лист на нём — четырёхугольник. Если привязать такое фото
линейной калибровкой, на краях листа ошибка доходит до сантиметров, и пометка уезжает на
соседнюю позицию. Поэтому считается проективное преобразование (гомография) по четырём
углам рамки:

```
4 точки на фото (x, y)  ──H──▶  координаты чертежа (X, Y), мм
```

Дальше два шага, оба в модуле `pto_agent/cad/vision/perspective.py`:

1. **Выпрямление** — фото пересчитывается в «фронтальный» растр листа заданного размера
   (по умолчанию 3000 px по ширине). После этого работает весь обычный конвейер: тайлы,
   VL-модель, проверки, координаты. Модель видит ровный лист с ровным светом, а не наклонный.
2. **Выравнивание света** — делим снимок на его сильно размытую копию: виньетка и лампа
   сбоку исчезают, поле листа становится белым. Без этого шага «серое» поле перестаёт
   отличаться от графики и офлайн-детектор даёт ложные пометки.

Опорные точки ставит человек: отмечает четыре угла рамки листа и указывает, каким углам
чертежа они соответствуют. Автоматического поиска углов в модуле нет намеренно —
на фотографии с бликами и посторонними предметами он ошибается молча, а ошибка калибровки
уводит все пометки сразу.

### Что модуль проверяет до распознавания

| Проверка | Что происходит при отказе |
|---|---|
| Меньше 4 точек | `PerspectiveError`: для перспективы нужно 4 пары «пиксель ↔ мм» |
| Точки на одной линии / вырожденный четырёхугольник | отказ: «выберите углы листа, а не точки на одной стороне» |
| Точки переставлены («бабочка») | отказ: четырёхугольник на фото должен быть выпуклым, порядок — по часовой стрелке |
| Остаток на точках > 20 мм | предупреждение `PERSPECTIVE_RMS_HIGH`: точки поставлены неточно |
| Тёмный снимок (яркость < 95) | `PHOTO_DARK`: переснимите при лучшем свете |
| Блики (локально ярче медианной яркости листа на 35) | `PHOTO_GLARE`: часть пометок может пропасть |
| Смаз | `PHOTO_BLURRY`: держите телефон неподвижно |
| Калибровка не подтверждена человеком | `CALIBRATION_NOT_CONFIRMED` в каждом ответе |

## 4. Пакетная обработка: выпуск целиком

```
манифест выпуска (JSON: лист → скан, чертёж, точки, тексты)
   │
   ├─ по каждому листу: распознавание → план операций → проверка по шаблону
   ├─ кеш: out/cad/batch/sheets/<лист>.json (по хэшу скана — повтор не тратит GPU)
   ├─ ошибка листа не роняет пакет: лист помечается причиной, остальные идут дальше
   └─ сводка: XLSX (6 листов) + Markdown + JSON
```

### Что в сводке

| Лист XLSX | Содержимое |
|---|---|
| «Итог» | листов, успешно/ошибок, пометок, автоматически/человеку, операций, конфликтов, калибровок без подтверждения, время |
| «Листы» | по каждому листу: пометок, авто, человеку, операций, конфликтов, состояние калибровки, ошибка, из кеша ли |
| «Конфликты» | лист, пометка, тип, позиция (шифр расценки), текст пометки, что делать |
| «Вопросы человеку» | лист, пометка, причина, предлагаемое действие |
| «Пометки по типам» | обводка / подчёркивание / перечёркивание / стрелка |
| «Конфликты по позициям» | на каких шифрах расценок копятся расхождения — это и есть «где болит» |

Сводка не прячет неприятное: если калибровка листа не подтверждена, если лист упал
с ошибкой, если пометок без текста больше половины — это отдельные строки, а не сноска
мелким шрифтом.

### Манифест

```json
{
  "release": "ЖК «Северный», корпус 2 — выпуск исполнительных схем 03.11.2026",
  "sheets": [
    {"sheet_id": "К2-АР-01-v01", "title": "К2-АР-01 · Фундаментная плита · итерация 1",
     "scan": "data/demo/batch/scans/К2-АР-01-v01.png",
     "drawing": "data/demo/batch/drawings/sheet_01.dxf",
     "anchors": "…/anchors.json", "texts": "…_texts.json", "truth": "…/truth.json"}
  ]
}
```

`anchors` нужен для фото (4 точки), `texts` — тексты, введённые инженером, `truth` — только
для режима `mock`. Можно указать не манифест, а каталог со сканами и чертёж по умолчанию:
`cad scan-batch --dir scans --file drawings/korpus2_plan_v1.dxf`.

## 5. Демо-выпуск: 40 листов

Структура как в работе: 4 листа комплекта (К2-АР-01…04, разные виды работ и шифры в штампе)
× 10 итераций правок. В каждом скане 4–7 пометок: смена диаметра, объём против акта,
исключение работ, «СОГЛАСОВАНО» на позиции с расхождением, ссылка на АОСР, уточнение класса
бетона — и часть пометок без подписи (уходят человеку).

| Прогон | Листов | Пометок | Авто | Человеку | Операций | Конфликтов | Время |
|---|---|---|---|---|---|---|---|
| `--engine mock` (идеальное чтение текста) | 40 | **205 из 205** | 156 | 49 | 226 | 43 | 202 с |
| `--engine offline` (без модели, тексты инженера) | 40 | 180 из 205 (88 %) | 122 | 58 | 164 | 40 | 247 с |

Конфликты: 20 по объёму (1300 м3 против 1240 м3 в акте) и 23 «согласовано там, где ПТО видит
критичное расхождение» — все на позиции ФЕР 06-01-001-01. Это и есть ответ на вопрос
«что показывает сводка»: не «всё хорошо», а конкретный шифр расценки, по которому спорят
чертёж и акт.

Разница 88 % против 100 % — честная цена режима без модели: офлайн-детектор ищет геометрию
(обводку, подчёркивание, стрелку) и не читает рукописный текст; близко стоящие пометки
(например, обводка «СОГЛАСОВАНО» и подчёркивание подписи рядом) иногда склеиваются в одну.

## 6. Команды

```bash
# фото с телефона: 4 угла листа → выпрямление → пометки
python3 scripts/make_demo_photo.py                       # демо-фото + опорные точки
python3 -m pto_agent cad scan --scan drawings/redline_photo.jpg \
        --file drawings/korpus2_plan_v1.dxf --engine vlm \
        --anchors data/demo/photo_anchors.json --rectified out/cad/photo_rectified.png

# тот же путь до операций и применения (HITL)
python3 -m pto_agent cad redline-from-scan --scan drawings/redline_photo.jpg \
        --file drawings/korpus2_plan_v1.dxf --engine offline \
        --anchors data/demo/photo_anchors.json --texts data/demo/redline_texts.json \
        --mode plan_only

# выпуск целиком
python3 scripts/make_demo_batch.py                        # 40 листов + манифест
python3 -m pto_agent cad scan-batch --manifest data/demo/batch/manifest.json \
        --engine vlm --out out/cad/batch
python3 -m pto_agent cad scan-batch --manifest data/demo/batch/manifest.json \
        --engine offline --out out/cad/batch_offline --no-resume

# MCP: тот же выпуск одним вызовом внешнего агента
# tools/call scan_release_batch {"manifest_path": "…", "engine": "vlm"}
```

Код возврата `scan-batch` = 1, если хотя бы один лист упал с ошибкой (чтобы это ловил CI,
а не «зелёный» отчёт).

| Сводка | агрегаты считаются верно (пометки, конфликты по типам, позиции, калибровки без подтверждения, упавшие листы) |

## 8. Честные ограничения

1. **Дисторсия объектива не компенсируется.** Гомография выправляет наклон плоскости листа,
   но не «подушку» широкоугольной камеры. На кадрах с сильной дисторсией нужно либо снимать
   с оптическим зумом, либо добавлять модель дисторсии (следующий шаг).
2. **Лист должен быть плоским.** Изогнутый лист (на весу, с загибом) даёт ошибку в местах
   изгиба; 4 точки описывают плоскость, а не поверхность.
3. **Опорные точки ставит человек.** Это осознанно: ошибочная авто-калибровка портит все
   пометки разом и незаметно.
4. **Демо-данные синтетические.** Фото и 40 сканов сгенерированы (шум, наклон, виньетка,
   JPEG), но не сняты реальной камерой; реальные снимки темнее и с бликами от ламп.
5. **Потоки только для модельного движка.** Офлайн-режим рендерит эталон через matplotlib,
   который не потокобезопасен, — при `--workers > 1` потоковка отключается с примечанием
   в сводке, а не падает молча.
6. **Кеш — по хэшу скана и движку.** Если поменялся шаблон или сводка ПТО, лист нужно
   пересчитать: `--no-resume`.
7. **Офлайн-режим на выпуске находит 88 % пометок** — этого достаточно, чтобы считать объём
   работы, но для операций нужен текст, то есть модель или ручной ввод.

## 9. Что дальше

1. Модель дисторсии объектива (2–3 коэффициента) — снимать без оптического зума.
2. Пакетная обработка с прогрессом в интерфейсе и возобновлением после обрыва (частично есть:
   кеш), плюс распределение листов по нескольким GPU.
3. Сводка «выпуск → КС-2»: агрегировать конфликты по позициям в предложения по корректировке
   акта (сколько денег стоит каждый конфликт) — это уже прямой выход на руководителя.
4. Автоподсказка четырёх углов как *предложение* инженеру (с обязательным подтверждением).
