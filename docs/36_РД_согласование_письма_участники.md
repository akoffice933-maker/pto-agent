# Круг 12. Выдача РД, согласование ИД, переписка, лаборатории и дни качества

Последний круг очереди: он закрывает оставшиеся пять обязанностей ПТО из 18 — контроль выдачи
рабочей документации со статусом «В производство работ», сопровождение ИД до согласования и
подписания, официальные запросы и письма, привлечение лабораторий и геодезистов, авторские дни и
дни качества. Общий знаменатель у них один: **у каждого действия должно быть основание, адресат
и след в документе**. Именно это и проверяют два новых модуля.

## 1. Пробелы, которые воспроизводились

| Что происходило | Чем это плохо |
|---|---|
| Бетон армировали и бетонировали по РД в редакции изм. 0, а изм. 1 вышел за неделю до работ | работа выполнена по заменённому документу: переделка за счёт подрядчика, и доказать нечего |
| РД передали «для ознакомления», без штампа «В производство работ», а работы начали | право работать по этой передаче не подтверждено; штамп — это и есть разрешение |
| Передача оформлена, но подписи получившего нет | формально документация «ушла», фактически — неизвестно куда и когда |
| Комплект ИД подписали, хотя два замечания технадзора не закрыты | подпись при невыполненных замечаниях недействительна, а узнали об этом на приёмке |
| Замечание со сроком 14 октября висело открытым до декабря | просрочка не видна, потому что срок нигде не считается |
| Комплект передали повторно теми же файлами, без отметки об устранении | это та же передача, а не устранение замечаний |
| Требование к генподрядчику отправили письмом, в котором не было ни пункта договора, ни нормы | требование не на чем основать — его можно отклонить одной строкой |
| Запрос без указания срока ответа | «ждём» месяцами; спросить нечего |
| Протокол испытаний грунта приняли от лаборатории, у которой аттестат истёк до даты испытания | результат на дату работы силы не имеет — это выясняется на экспертизе |
| Исполнительная съёмка «есть», но непонятно, к какой работе она относится | в комплект ИД такой документ не ложится |
| День качества «провели», протокола нет, замечание без ответственного и срока | мероприятие не дало ни одного последствия |

## 2. Модуль `pto_agent/docflow.py` — выдача РД и согласование ИД

Схемы `pto-agent/rd-issue@1` и `pto-agent/submittals@1`.

### Реестр выдачи РД

Проверки:

- `RD_NO_DATE` — передача без шифра, даты или получателя в реестр не попадает (ошибка);
- `RD_WITHOUT_STAMP` — передача без штампа «В производство работ»: работать по ней нельзя
  (предупреждение, а состояние документа — «не выдана»);
- `RD_WITHOUT_RECEIPT` — нет подписи получившего: передача не подтверждена (ошибка);
- `RD_REPLACED_IN_WORK` — в производство выдана редакция, которая уже заменена (ошибка);
- `RD_UNKNOWN_REVISION` — редакции нет в реестре редакций (ошибка);
- `RD_DUPLICATE_TRANSMITTAL` — та же дата, редакция и получатель (предупреждение);
- `WORK_WITHOUT_RD` — **стык с актами и журналом**: работа ссылается на РД, которой нет в
  реестре выдачи или которая передана без штампа (ошибка).

По каждому документу считается состояние: `в производстве`, `не выдана`, `заменена`.
`can_work` отвечает, можно ли считать, что документация для производства работ есть, и объясняет
отказ.

### Реестр согласования ИД

Цикл «передан → замечания → устранено → передан повторно → согласовано/подписано»:

- `SIGNED_WITH_OPEN_REMARKS` — комплект подписан при открытых замечаниях: подпись
  недействительна (ошибка), статус «подписан с открытыми замечаниями»;
- `SIGNED_ANONYMOUS` — подпись без ФИО и роли подписью не является (ошибка);
- `REMARK_OVERDUE` — срок устранения прошёл (ошибка); `REMARK_WITHOUT_DUE` — срок не указан
  (предупреждение);
- `RESUBMIT_WITHOUT_FIX` — повторная передача без отметки об устранении хотя бы одного
  замечания: это та же передача (ошибка);
- `SUB_WITHOUT_RECEIPT` — нет отметки о получении (предупреждение);
- `REMARK_WITHOUT_ANSWER` — текст замечания не записан (предупреждение).

`can_close` перечисляет, что мешает сдавать комплект. Подпись реестра — только с ФИО и ролью и
только при отсутствии открытых замечаний.

## 3. Модуль `pto_agent/correspondence.py` — письма, участники, дни качества

Схемы `pto-agent/letters@1`, `pto-agent/involvement@1`, `pto-agent/quality-days@1`.

### Письма и запросы

- `LETTER_NO_NUMBER` / `LETTER_NO_DATE` / `LETTER_NO_ADDRESSEE` — в реестр не попадает;
- `LETTER_NO_BASIS` (ошибка) — нет основания (пункт договора, норма, номер письма): требование
  предъявлять нечем;
- `LETTER_NO_SIGNER` (ошибка) — нет ФИО и роли подписавшего: письмо не считается отправленным;
- `ANSWER_OVERDUE` (ошибка) — срок ответа прошёл, ответа нет; `ANSWER_MISSING`
  (предупреждение) — ответа пока нет, срок не наступил; `ANSWER_WITHOUT_REFERENCE` —
  ответ без номера и даты, сослаться нельзя;
- `LETTER_DUPLICATE_NUMBER` — два письма под одним номером.

`open_requests` — список «ждём ответа» с пометкой просрочки.

### Лаборатории и геодезисты

- `NO_ACCREDITATION` (ошибка) — нет аттестата: результат в комплект ИД не принимается;
- `ACCREDITATION_EXPIRED` (ошибка) — аттестат истёк **до даты работы**, а не «сегодня»:
  результат на дату работы силы не имеет;
- `SCOPE_NOT_STATED` (предупреждение) — область аккредитации не указана, проверить нечем;
- `RESULT_UNLINKED` (предупреждение) — результат не привязан к партии, работе или акту;
- `RESULT_MISSING` (предупреждение) — результата ещё нет; `RESULT_OVERDUE` (ошибка) — срок
  прошёл;
- `DUPLICATE_REQUEST` — дубль заявки.

### Авторские дни и дни качества

- `EVENT_NO_PARTICIPANTS` (ошибка) — мероприятие без участников не проводится;
- `EVENT_NO_PROTOCOL` (предупреждение) — протокола нет, замечания и решения не зафиксированы;
- `EVENT_REMARK_NO_RESPONSIBLE` / `EVENT_REMARK_NO_DUE` (предупреждения) — исполнять некому /
  просрочку не увидеть;
- `EVENT_REMARK_OVERDUE` (ошибка) — срок прошёл, замечание не закрыто.

## 5. Как пользоваться

```bash
# выдача РД: какая редакция, кому, со штампом ли, есть ли подпись получившего
python3 -m pto_agent docflow --out out/docflow rd \
  --transmittals data/demo/docflow/transmittals.json \
  --revisions data/demo/docflow/revisions.json \
  --works data/demo/docflow/works_rd.json --number РД-1

# согласование ИД: замечания, сроки, повторная передача, подпись
python3 -m pto_agent docflow --out out/docflow submittals \
  --submittals data/demo/docflow/submittals.json --number СГ-1

# письма и запросы
python3 -m pto_agent correspondence --out out/corr letters \
  --source data/demo/correspondence/letters.json --number ПИС-1

# лаборатории и геодезисты, авторские дни и дни качества
python3 -m pto_agent correspondence --out out/corr involvement \
  --source data/demo/correspondence/involvement.json --number ЛАБ-1
python3 -m pto_agent correspondence --out out/corr days \
  --source data/demo/correspondence/quality_days.json --number ДК-1

# подпись реестра: ФИО и роль обязательны
python3 -m pto_agent docflow --out out/docflow sign \
  --registry out/docflow/rd_РД-1.json --by "Иванов И.И." --role "начальник ПТО"
```

Коды возврата: `0` — ошибок нет (или реестр подписан), `2` — есть ошибки либо подпись отклонена.

MCP: `docflow` (`rd`/`submittals`/`sign`) и `correspondence`
(`letters`/`involvement`/`days`/`sign`) — 30 → **32 инструмента**, `prompts/tools_schema.json`
версии 2.3.0 (по 7 guardrails на инструмент).

## 7. Чего эти реестры не делают

- **Не разрешают работы.** Разрешение — это передача РД заказчиком со штампом «В производство
  работ». Агент лишь сверяет, что ссылка в акте ведёт на действующую редакцию и подпись
  получившего есть.
- **Не согласовывают ИД.** Согласование и подпись оформляет технадзор и заказчик; агент
  не даёт подписи появиться раньше закрытия замечаний.
- **Не пишут письма.** Письмо готовит и подписывает человек; реестр показывает, есть ли
  основание, адресат и ответ в срок.
- **Не заменяют аккредитацию.** Реестр сверяет аттестат и дату работы; область аккредитации
  подтверждает сама лаборатория.
