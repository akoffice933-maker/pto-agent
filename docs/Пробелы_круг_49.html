Круг 49. Проверка трёх «пробелов»

Запрос: найти в интернете или на GitHub пробел по трём пунктам — ТЕР, индексы пересчёта, реестр отчётности и данные заказчика. Проверялось запросами к API и разбором скачанных файлов, а не рассуждением. Дата проверки: 18 ноября 2026.

ПРОБЕЛА НЕТ

Индексы пересчёта

Заявлялось: письма Минстроя, ручной импорт. На деле письма лежат в открытом API ФГИС ЦС и скачиваются без авторизации. Автоматизация была не найдена, а источник есть.

2 905 значения разобрано из 6 писем III квартала 2026.

ПОДТВЕРЖДЕНО ЧАСТИЧНО

ТЕР

Заявлялось: в открытых данных только федеральная база, сборники — PDF на региональных сайтах. Для расценок верно. Для реквизитов — нет: реестр ФРСН открыт и машиночитаем.

846 записей реестра, расценок — ноль.

НЕВЕРНО, НО НЕДОСТИЖИМО

Реестр отчётности / данные заказчика

Заявлялось: внешнего источника не существует. Источник есть — ЕИС. Но из этой среды канал не работает; для нас данные по-прежнему только от заказчика.

FTP: баннер не пришёл. HTTPS: TLS оборван.

1. Индексы пересчёта: это не «руками», это API

Что сделано

scripts/import_indices.py скачивает дерево и разбирает PDF в таблицу data/indices/minstroy_indices.csv.gz. Формат «длинный»: одна строка — одно значение, с обязательными полями letter (письмо), table_title (дословная шапка таблицы из PDF) и page (страница). Поэтому каждую цифру можно открыть в письме и сверить.

Почему не «по колонке на вид индекса»: состав приложений в письмах разный. В 53691-АЛ/09 есть приложение «Автомобильные дороги / Искусственные дорожные сооружения», в 45358-ИФ/09 его нет вовсе, зато есть «перевозка грузов автомобильным транспортом». Широкая таблица молча потеряла бы различие.

В смете проверить так: python3 -m pto_agent indices --subject "Краснодарский край"

Границы разбора — честно. Разбираются таблицы вида «№ п/п | субъект | числа». Приложения «по объектам строительства» и «по элементам прямых затрат» свёрстаны с объединёнными ячейками и вертикальными заголовками (на стр. 6 слово «Московская область» набрано по буквам в столбик) — они остаются только в PDF. В отчёте стоит факт — 2 905 значений, а не «сколько должно быть».

Отдельно проверено: эндпоинт IndicesOfChangeEstimatedPrice, который по названию должен отдавать индексы, при всех комбинациях параметров возвращает {"total":0,"items":[]}. То есть документы-письма в API есть, а нормализованной таблицы индексов — нет.

2. ТЕР: реестр открыт, расценок в машиночитаемом виде нет

Заявление «в открытых данных ФГИС ЦС только федеральная база» верно для расценок и неверно для реквизитов.

GET /api/FrsnEdition/section                      → раздел 3 = территориальные нормативы
GET /api/FrsnEdition/Estimate/Section?section=6   → 845 записей
GET /api/FrsnEdition/Estimate/Section?section=7   → 1 запись

Актуальность реестра на дату запроса: 06.11.2026. Всего 846 записей; регион удаётся выделить из наименования у 605 записей (30 субъектов), у 241 записи регион в названии не указан — они внесены общей формулировкой, и колонка остаётся пустой, а не заполняется догадкой.

Чего нет — и как это проверено

  1. Таблиц расценок нет в API ФРСН. FrsnEdition/Estimate/Section отдаёт наименование, приказ, рег. номер, editionId и ссылку — полей с расценками нет.
  2. ТЕР нет в архиве ФСНБ-2022. Разбор официального ZIP через zipfile: 7 XML — ГЭСН, ГЭСНм, ГЭСНмр, ГЭСНп, ГЭСНр, ФСБЦ_Мат&Оборуд, ФСБЦ_Маш. Ни одного файла ТЕР. (grep по «ТЕР» в этих XML даёт ложные срабатывания — это слово «диаметр».)
  3. Ссылки реестра ведут на недоступный хост. 662 записи имеют ссылку, 648 из них — один адрес view.territorial.php. Проверка: DNS отдаёт 82.202.190.8, TCP/TLS не отвечает (curl код 000), fetch_page → HTTP 500.
  4. На GitHub данных ТЕР нет. Поиск по «ФРСН», «ТЕР расценки», «смета parser» — репозиториев с таблицами ТЕР нет. proovcme/fgis-mcp (MIT) фиксирует то же разделение: ТЕР = подразделы 6/7 ФРСН со внешними ссылками. ErvSed/smeta-fsnb-data — SQLite из открытых данных, только федеральная база.
Вывод. «Сборники ТЕР — региональные сайты и PDF» — верно. «В открытых данных только федеральная база» — верно для расценок. Добавленная ценность: теперь список сборников по региону с приказами получается автоматически. Оговорка: наличие записи в реестре не означает, что сборник действует в актуальной редакции — реестр даёт реквизиты внесения, а не статус.

3. Реестр отчётности и данные заказчика: источник есть, но недостижим

Единственный пункт, где проверка не дала окончательного ответа, — и это зафиксировано как есть.

Реестр контрактов и отчётности по 44-ФЗ публикуется в ЕИС, включая FTP-выгрузку открытых данных. На GitHub есть рабочие инструменты под неё: Homyakin/ZakupkiParser (MIT), aksyuk/zakupki_gov_ru (MIT), stufently/free-zakupki-gov-ru-monitor (MIT). Значит, источник существует и машиночитаем.

Что это значит. «Внешнего источника не существует» — неверно: источник есть. Но «данные заказчика — только данные организации» остаётся верным для нас: пока канал недостижим, эти данные можно получить только от заказчика. Это ограничение доступа из конкретной сети, а не отсутствие источника. data.gov.ru в 2026 отдаёт JS-SPA на любой путь, включая /api/json/dataset, — прежний API открытых данных не работает.

Не сделано

  1. Расценки ТЕР не получены. В машиночитаемом виде их нет ни в одном открытом источнике; ссылки реестра ведут на недоступный хост. Демо-ставки остаются как fallback с пометкой.
  2. Разобрано не всё содержимое писем. Приложения «по объектам строительства» и «по элементам прямых затрат» в CSV не попали; в письмах 50058-ИФ/09 и 52419-ИФ/09 таблиц нужного вида нет — 0 значений.
  3. ЕИС проверен только на доступность. Содержательно данные не скачаны: канал не работает.
  4. Индексы не подключены к расчёту сметы. Модуль отдаёт значение с источником, но пересчёт базисной стоимости в текущую автоматически не выполняется — нужно решить, к каким позициям применяется каждая колонка.
  5. Актуальность редакций ТЕР не проверена. Реестр даёт реквизиты внесения, а не статус.
