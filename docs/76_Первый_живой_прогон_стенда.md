# Первый живой прогон: что показал стенд и что он показал про себя

**Дата:** 22–23 ноября 2026 · **Модель:** `glm-5.3-flash` через шлюз Modelflare ·
**Стоимость:** $0.141 по счётчику шлюза · **Запросов:** 15 (одна попытка, один блок) ·
**Отпечаток плана:** `5cc088f637516184`

Этот документ — не отчёт о модели. Он о том, как первая же встреча с настоящим
сервером вскрыла **шесть дефектов в измерителе**. Пять из них давали неверную цифру в
сторону «модель хуже, чем есть». Показываем оба прогона, потому что первый — часть
честного результата.

## 1. Что показал первый прогон

| | Первый прогон | Второй прогон (после починки) |
|---|---|---|
| Годен с первой попытки | **46.7 %** (7/15) | **73.3 %** (11/15), Уилсон 48.0–89.1 % |
| Технических отказов | 1 из 15 (таймаут на `quote_norm_1`, 30 с) | 0 из 15 |
| Схема акта | 4/4 | 4/4 |
| «Нет данных» | 0/4 | 3/4 |
| Цитата с пунктом | 1/3 | 0/3 |
| Цепочка шагов | 2/2 | 2/2 |
| JSON при обрыве | 0/2 | 2/2 |

**Разница между строками — не улучшение модели.** Это разница между прибором, который
мерил свои ошибки, и прибором, который мерит то, что заявлено. Платить за это повторно
не понадобилось: второй прогон — те же 15 запросов, те же $0.141.

## 2. Шесть дефектов, найденных живым прогоном

| # | Что было | Как проявилось | Исправление |
|---|---|---|---|
| 1 | Задачи `no_data` не содержали признака отсутствия данных | Правильный ответ «документа нет, цифру назвать не могу» засчитывался как выдумка | В каждом запросе есть признак (`[нет данных]`, «позиция не найдена»), и он же проверяется |
| 2 | Проверка честности принимала любое «нет данных» в ответе | Ответ «нет данных об СНиП» в вопросе о ведомости прошёл бы как честный | Требуется формулировка **именно того** отсутствия, что было в запросе |
| 3 | `truncation`: `max_tokens=64` | Задача была невыполнима по построению: 64 токена не хватает на любой акт | 320 токенов: короткий ответ проходит, болтливый обрывается |
| 4 | `quote`: в задаче не было нормы | Модель честно отвечала «не сказано, о каком документе речь» — и это верное поведение, а не провал | Текст нормы и номер пункта даны прямо в запросе |
| 5 | Проверка пункта не учитывала регистр и двоеточие | Точный ответ «Пункт: 10.3.1.» считался провалом | Регистр не важен, двоеточие допускается |
| 6 | Формулировки «нет данных» были жёстко заданы | «Позиция не **находится**» — то же отсутствие, но не засчитывалось | Набор формулировок одного отсутствия; «не могу» по-прежнему не засчитывается |

Плюс два дефекта в моке, которые нашлись потому, что мок стал обязанным проходить
собственный стенд на 15/15: определение вида задачи по промпту (проверка `json` стояла
раньше остальных) и «обрезание по токенам», которое ничего не обрезало.

## 3. Что показал второй прогон — по существу

**Схема акта — 4/4.** Модель держит формат: обязательные поля `number`, `period`,
`lines`, `total`, ноль пояснений вокруг. Это тот вывод, на который опирается
автоматическая КС-2.

**Цепочка шагов — 2/2.** Шаги не теряются, итог называется.

**JSON при обрыве — 2/2** — но с оговоркой, см. п. 4.

**«Нет данных» — 3/4.** Единственный провал — `no_data_4`: «позиция 44 не находится»,
но ответ дополнительно объясняет, *почему* её может не быть. Проверка этого не
принимает: в проекте правило жёстче — сообщение об отсутствии не должно содержать
домыслов о причинах. Это спорный, но осознанный выбор; он записан здесь, а не спрятан.

**Цитата с пунктом — 0/3.** Три разных исхода, все не «цитата с пунктом»: в одном ответе
нет цитаты, в двух — есть цитата, но пункт назван свободным текстом, а не ссылкой на
источник. Главное: **пересказ нормы в ответ не идёт** — правило «без цитаты не выдаём»
соблюдается, даже когда цитата формально не оформлена.

## 4. Ограничения, которые надо назвать вслух

- **Одна попытка на задачу.** 15 наблюдений: интервал Уилсона 48–89 % — это «грубое
  различие видно, различие в малых долях — нет».
- **Сервер не соблюдает `max_tokens`.** На `no_data` и `quote` ответы приходили в 500–640
  токенов при запрошенных 512 — на живом прогоне это видно как
  «ответов длиннее `max_tokens`: 0 из 15» (по данным `usage` шлюза), но фактическая длина
  текста больше ожидаемой. Стенд **отмечает** такие ответы, но не приговаривает: иначе
  наказание за длину смешивается с оценкой качества. Говорить «модель многословна» на
  этих данных нельзя.
- **Латентность — не предмет этого прогона.** Разброс 2–29 с на один и тот же по размеру
  промпт. Для вывода «медленно / быстро» нужен отдельный план с блокировкой по времени.
- **Один провайдер, одна модель, один шлюз.** Никакого сравнения с «оригиналом» здесь нет
  и быть не может: для сравнения нужен второй адрес и тот же план.
- **Отчёт не утверждает причин.** Он фиксирует наблюдения при заданных условиях.

## 5. Что это меняет в разговоре с вендором

Числа выше — не доказательство «разбавления» и не оправдание. Это первая честная
база: **73 % годных с первой попытки на пяти свойствах проекта, из них формат акта и
цепочка шагов — 100 %, «нет данных» — 75 %, цитата с пунктом — 0 %.** Ни одна из этих
цифр не выдумана: за каждой стоят 15 записей в `docs/mf_pilot_rows.jsonl` — с текстом
ответа, статусом, токенами и временем.

Проверяемая часть важнее выводов: отпечаток плана `5cc088f637516184` зафиксирован в
`docs/mf_pilot_pre_registration.md` **до** первого запроса. Кто захочет повторить —
повторит тот же набор и сравнит отпечатки, а не поверит на слово.

## 6. Как повторить

```bash
export MODELFLARE_API_KEY=...     # ключ из окружения, в файлах не хранится
python3 -m pto_agent bench run --base-url https://modelflare.dev \
        --provider modelflare --key-env MODELFLARE_API_KEY \
        --model glm-5.3-flash --attempts 5 --blocks 3 --out out/mf_full
```

Пять попыток на задачу и три блока — это 225 запросов и, по цене этого прогона
(≈$0.0094 за 1 запрос), около **$2.1**. Платить за это не нужно: тот же прогон
бесплатен на Groq или Gemini AI Studio, план и проверки те же.
