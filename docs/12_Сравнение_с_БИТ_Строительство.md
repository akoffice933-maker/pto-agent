# Сравнение с БИТ.Строительство (1С) и схема стыковки

Документ отвечает на два вопроса: **чем мы отличаемся** от отраслевой ERP на 1С и **как
соединить** их так, чтобы не было двойного ввода. Данные о продукте сверены с публичными
материалами вендора 2026-11-03 (ссылки в конце) — цены и состав модулей меняются, перед
закупкой их надо перепроверять у «Первого Бита».

## 1. Терминология: что именно сравниваем

* Продукт называется **БИТ.Строительство** (разработчик — «Первый Бит»), это модульная
  надстройка над 1С:Бухгалтерией/УНФ, входит в Реестр российского ПО. Формулировка
  «1С БИСТ ПТО» — обиходная: отдельного продукта с таким названием нет.
* Модулей в линейке **16**, они покупаются по отдельности. Задачи ПТО распределены между
  несколькими: **Основная поставка** (КС-2, КС-3, М-29, пообъектный учёт), **Подрядчик**
  (собственные и субподрядные СМР, ПБУ 2/2008, гарантийные удержания), **Управление
  строительными проектами** (календарно-ресурсное планирование, план-факт по объёмам),
  **Документооборот** (архив, маршруты согласования, ЭП, Гантт), **Строительный контроль**,
  **Проектирование и составление смет** (загрузка сметной документации, КС-6а).
* Ориентиры по цене из публичного прайса: «Основная поставка» ≈ 30 000 ₽,
  «Управление строительными проектами» ≈ 150 000 ₽/год; внедрение и сопровождение — отдельно.

Вывод по терминологии: это **учётная система с отраслевыми формами**, а не «ПТО-модуль».
Именно поэтому сравнение с нашим агентом — не «кто лучше», а «кто что закрывает».

**Объективный счёт:** учёт, финансы, планирование, архив и печатные формы — территория БИТ
(≈ 12 из 26 строк матрицы). Проверка данных, деньги спора, vision, CAD и MCP — наша территория
(≈ 10 строк). Пересечение — контроль лимитов и КС-2: там мы считаем, а они хранят.

## 3. Где мы честно слабее

1. **Нет учёта.** Мы не храним объект, договор, субподряд, склад, платежи. «Портфель актов»
   у нас — файл-реестр, а не база с историей и правами.
2. **Нет печатных форм.** Черновик КС-2 мы отдаём в XLSX; утверждённые формы КС-2/КС-3/КС-6а
   с подписями — зона 1С.
3. **Нет ЭП, маршрутов согласования и архива ИД.** У нас есть чек-лист комплектности, но не
   электронный архив с юридически значимой подписью.
4. **Нет планирования.** Графики, ресурсы, Гантт — не наша зона; наш график — это деньги по
   месяцам, а не работы по неделям.
5. **MVP, а не продукт.** Нет поддержки вендора, SLA, обновлений под изменения законодательства.

## 4. Схема стыковки: три уровня, от простого к сложному

### 4.1. Уровень 1 — файловый обмен (реализован)

```
1С / БИТ                        pto-agent
смета (CSV)  ────────────────►  import-1c --smeta   → строки сметы для сверки
акты КС-2 (CSV) ─────────────►  import-1c --acts    → реестр актов → портфель, деньги под риском
проверенная КС-2 (CSV) ◄──────  export-1c --summary → загрузка документа в 1С
```

Контракт обмена (реализован в `pto_agent/integrations/one_c.py`):

| Направление | Файл | Колонки |
|---|---|---|
| из 1С | смета | `Код; Наименование; ЕдИзм; Количество; Цена; Сумма` |
| из 1С | акты | `Акт; Период; Дата; Статус; Код; Наименование; ЕдИзм; Количество; Цена; Сумма` |
| в 1С | проверенная КС-2 | `Код; Наименование; ЕдИзм; КоличествоАкта; КоличествоЖурнала; Цена; СуммаБезНДС` |

Правила, которые держит модуль: `utf-8-sig` + `;` + десятичная запятая при записи
(это то, что 1С и Excel читают без пляски с кодировками); терпимое чтение чужих шапок
(`Шифр`/`Код`, `Кол-во`/`Количество`, `Ед. изм.`/`ЕдИзм`), кодировок (cp1251) и разделителей
(`;`, таб, `,`, `|`); строка без объёма остаётся **не оценённой** и не попадает в сумму акта,
о чём пишется предупреждение.

```bash
# из 1С: смета и акты → наши структуры
python3 -m pto_agent import-1c --smeta выгрузка_сметы.csv --acts реестр_кс2.csv --out out/1c
# наш результат: деньги под риском и портфель по импортированным актам
python3 -m pto_agent cad impact --acts out/1c/acts_from_1c.json --summary out/summary.json \
        --out out/cad/portfolio
# обратно в 1С: проверенная КС-2 (объём к предъявлению, сумма по цене сметы)
python3 -m pto_agent export-1c --summary out/summary.json --out out/1c/ks2_for_1c.csv
```

### 4.2. Уровень 2 — HTTP-сервис 1С (реализован)

Файлы из процесса убираются, контракт полей остаётся тем же. Со стороны 1С публикуется
HTTP-сервис расширения с тремя методами:

| Метод | Что делает | Ответ |
|---|---|---|
| `GET /acts?period=YYYY-MM` | акты КС-2 с позициями (по периоду или `act_id`) | `{"acts": [{act_id, period, act_date, status, positions: [...]}]}` |
| `GET /estimates/{id}/lines` | строки сметы | `{"lines": [{Код, Наименование, ЕдИзм, Количество, Цена}]}` |
| `POST /validated-ks2` | приём проверенной КС-2 | `{"document": "КС-2 №99", "accepted": true}` |

Что делает наш клиент (`pto_agent/integrations/one_c_http.py`):

* **читает обе формы ответа** — вложенную (акт → позиции) и плоскую (строки с колонкой акта),
  а также вложенные объекты 1С вида `{"Стоимость": {"Сумма": 100}}`;
* **различает ошибки:** 401/403 → `OneCAuthError`, 4xx → `OneCRequestError` (не повторяем),
  5xx и обрыв сети → `OneCServerError` (повтор с задержкой);
* **идемпотентен:** `Idempotency-Key` = sha256 от канонического JSON, поэтому повторная
  отправка того же результата не создаст второй документ в 1С;
* **не отправляет нули вместо данных:** позиция без объёма уходит как `quantity: null`,
  `estimated: false` — 1С увидит, что её надо дозаполнить, а не «ноль».

```bash
# переменные окружения, не файлы: ONEC_URL / ONEC_USER / ONEC_PASSWORD (или ONEC_TOKEN)
python3 -m pto_agent sync-1c --config config/one_c.example.yaml --period 2026-09 \
        --summary out/summary.json --push --out out/1c
# результат: out/1c/acts_from_1c.json (портфель), out/1c/ks2_payload.json, out/1c/sync_log.json
```

Проверка: 21 тест на фейковом HTTP-сервисе 1С — аутентификация basic и по токену, 401 без прав,
4xx без повторов, 5xx с повтором, не-JSON ответ, вложенная и плоская формы актов, расчёт цены
из суммы, стабильность ключа идемпотентности, CLI целиком.

### 4.3. Уровень 3 — «программный робот» в 1С

Если менять конфигурацию нельзя, ставим на стороне 1С обработку, которая по расписанию
выгружает CSV в сетевую папку и забирает наш результат — то же, что уровень 1, но без человека.
Это самый дешёвый способ пройти пилот в компании, где 1С трогать не дают.

## 5. Что рекомендовать компании

| Ситуация | Решение |
|---|---|
| Уже работают БИТ.Строительство | оставить ERP как ядро учёта; подключить pto-agent на уровень 1 (файлы) — пилот за неделю, без доступа к 1С |
| Учёт есть, но акты проверяют глазами | pto-agent как обязательный контроль перед подписанием КС-2 + «деньги под риском» для руководителя |
| Много бумажных выпусков ИД | pto-agent: сканы, фото, пакетная обработка; реестры ИД остаются в БИТ.Документооборот |
| Только внедряют 1С | сразу проектировать обмен по уровню 2, чтобы не появился двойной ввод |
| Учёт не автоматизирован | начинать с pto-agent нельзя: контроль нечего проверять — сначала учёт |

## 6. Итог в одну строку

**БИТ.Строительство** отвечает на вопрос «что у нас есть и сколько мы потратили»,
**pto-agent** — «правда ли то, что нам предъявляют, и сколько стоит спор».
Они стыкуются по файлу или HTTP-сервису и почти не конкурируют: ERP — система записи,
агент — система контроля.
