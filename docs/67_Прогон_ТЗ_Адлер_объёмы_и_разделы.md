# Круг 46. Прогон по ТЗ «СКС Адлер»: объёмы, расхождения цифрами, разделы в выгрузке

**Пункт плана:** прогон на реальном документе после круга 45 («давай прогоним»).
**Документ:** `ТЗ Адлер.pdf` — 8 страниц, ПАО «ОГК-2», Адлерская ТЭС, шифр 240203-11-СКС.

## 1. Что прогнано и чем

```
python3 -m pto_agent prices import --file data/demo/prices_skc_adler.csv ...   # версия цен
python3 -m pto_agent takeoff --out <папка> tz --file "ТЗ Адлер.pdf" \
    --map data/reference/takeoff_map_tz.json --prices-dir <папка>/prices_store --as-of 2026-11-12
python3 -m pto_agent pack build --config data/demo/pack/pack.json     # комплект ИД
python3 -m pto_agent run --data data/demo --vat 22                    # сверка → КС-2
python3 scripts/check_tz_tables.py .github/tz/ТЗ_Адлер.pdf            # 35 проверок
```

Результат по объёмам: **97 объёмов** из 13 пунктов ТЗ, 12 позиций «не оценено» с причинами,
ведомость **96 строк с ценой**, итог **1 608 120,00 ₽**, на проверку 8, не включено 1.

## 2. Расхождения ТЗ — цифрами, а не «есть замечания»

* распределение по способам прокладки (оптика): 6 970 + 160 + 160 + 120 + 100 + 160 + 240 =
  **7 910** против общей длины **8 270** → расхождение **360 м**. Объём принят по итогу таблицы
  (8 270 м), расхождение названо и вынесено в отчёт;
* оговорка «исправлено с 5 до 6» при количестве **2 шт.** в п. 5.6.1 — противоречие внутри ТЗ,
  требуется письменное уточнение проектировщика; ни одно из чисел не выбрано «молча».

Обе проверки нашлись не в тестах, а на настоящем PDF — это и есть смысл прогона.

## 3. Три дефекта, которые прогон вскрыл

1. **`boq.csv` писал колонку `trade`, а не `раздел`.** Читатель (`read_boq`) ищет алиас
   «раздел»/«trade», поэтому строки читались, но ведомость собиралась одной плоской таблицей:
   деление на разделы работ пропадало. Теперь в выгрузке графа `раздел`, и в ведомости 13 разделов.
2. **Проза ТЗ (п. 5.4, 5.7, 5.8, 5.9) не имела названия раздела** — 14 строк попадали в пустой
   раздел. Добавлена таблица `prose_sections` в `_derive_prose`; пустых разделов больше нет.
3. **Проверки ТЗ не имели машинного признака.** CLI печатал «✓/!» по сравнению русской строки
   с «сходится», а markdown — то же самое. С появлением третьего состояния «не проверено»
   (мало чисел в строке распределения) такая проверка молча становилась «расхождением».
   Теперь у каждой проверки `ok: true | false | null`, CLI печатает `✓` / `!` / `·`,
   markdown — «сходится» / «**расходится**» / «не проверено».

## 4. Новый шаг CI

`scripts/check_tz_tables.py` — 35 проверок на реальном PDF (файл лежит в `.github/tz/ТЗ_Адлер.pdf`,
чтобы шаг не зависел от загрузок): страницы и таблицы, число объёмов, сварка 256 = 16 × 8 × 2,
расхождения названы числом (7910/8270/360), у проверок есть `ok`, «не оценено» без количества,
выгрузка знает раздел (13 разделов), стык с ценами (96 строк, 1 608 120,00 ₽), markdown совпадает
с JSON.

## 5. Чего прогон не дал — и это сказано прямо

* **сметы в ФЕР/ТЕР по Адлеру нет** — ведомость даёт объёмы и демо-ставки, а не смету;
* **КС-2 по Адлеру не считается**: в контуре нет сметы и журнала работ по этому объекту, поэтому
  сквозной `run` отработал на демо-данных ЖК «Северный» (21 271 000 ₽ к предъявлению) — это
  проверка механизма, а не денег Адлера;
* **комплект ИД** собрался по демо-конфигу другого объекта (7 разделов с ошибками, подписей 0);
* **оборудование** (шкафы, коммутаторы, ИБП, сервер) — поставка заказчика, в ведомость работ
  подрядчика не входит;
* **пусконаладка (п. 5.10)** не оценена целиком: работы названы, объёмов нет — «1 комплект»
  было бы выдумкой.
